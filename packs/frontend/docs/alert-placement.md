# 알림 표시 위치 (배너 · 토스트 · 인라인 · 다이얼로그)

## 기본 정책

**배너는 읽고 조치해야 하는 것만 담는다. 성공은 예외 없이 토스트다.** 성공에는 할 일이 없고, 배너는 화면에
남아 다음에 옮겨간 자리를 덮는다. 나머지는 그 동작을 일으킨 버튼 곁에 둔다 — 곁에 자리가 있으면 배너, 없으면 토스트.

| 버튼이 어디 있나 | 표시 | 이유 |
|---|---|---|
| 페이지 헤더 · 섹션 헤더 · 폼 | **배너** (헤더 아래) | 누른 시점에 그 자리가 이미 화면 안이다 |
| 드로어 · 다이얼로그 안 | **배너** (패널 본문 상단) | 패널 스크롤은 짧고 국소적이다 |
| **표의 행 안** (휴지통 · 연필) | **토스트** | 배너 자리가 화면 맨 위라 긴 목록에서 안 보이고, 끌어올리면 보던 행을 잃는다 |
| **성공** | **토스트** | 배너로 두면 다음 행으로 옮겨간 뒤에도 남아 그 자리의 결과처럼 읽힌다 |
| 입력값 검증 | **필드 아래 인라인** | 어느 칸이 틀렸는지는 그 칸 옆에서만 말이 된다 |
| 되돌릴 수 없는 확인 | **다이얼로그** | `confirm-dialog.md` |

- 행 액션이 오류에서도 토스트인 이유 — 오류에 배너를 권하는 업계 가이드(Polaris · NN/G)는 **배너가 동작 근처에 있다**는 전제다. 긴 목록의 행에는 그 전제가 없다. 대신 토스트 문구를 **조치 중심으로 짧게** 쓴다. 그래도 부족하면 행 자체에 표시하는 방식을 검토한다.
- **그 밖의 오류를 토스트로 띄우지 않는다** — 사라지는 오류는 못 본 것과 같다.
- **검증 오류를 배너·토스트로 대신하지 않는다.** 서버 `errors[]` 는 `field` 를 주므로 그 필드 아래에 붙인다. 필드가 특정되지 않는 것(표 편집처럼 필드 슬롯이 없는 화면, 서버가 `field` 없이 메시지만 준 경우)만 배너.
- 확인 다이얼로그 안의 동작이 실패하면: 배너가 다이얼로그 안이면 **닫지 않는다**(사유가 함께 사라진다), 행 액션이라 토스트로 나가면 닫는다.

## 배너 — 공용 배너 헬퍼 하나

프로젝트에 배너를 띄우는 공용 헬퍼(React 는 훅, Angular 는 서비스 등) 하나를 두고 화면은 그것만 쓴다. 아래 이름은 예시다.

```tsx
// React 예시
const alert = usePageAlert()
alert.showApiError(error, 'Failed to delete the order.')   // 색은 응답 코드가 정한다 (5xx danger / 4xx warning)
alert.showWarning('Select at least one row.')

<PageHeader title="Orders">{actions}</PageHeader>
{alert.node}
```

| 메서드 | 쓰임 |
|---|---|
| `showApiError(error, fallback)` | mutation 실패. 서버 메시지 우선. **401·403 은 건너뛴다**(전역 처리). danger 이고 추적 ID 가 있으면 code 줄을 붙인다 |
| `showWarning` · `showDanger` | 한 줄. **`showSuccess` 는 없다** — 배너 타입에서 success 를 빼서 컴파일이 막게 한다 |
| `show({ type, title?, message })` | 제목·JSX 본문이 필요할 때 |
| `clear()` · `clearIf(target)` | 새 시도 시작 시 · 내가 띄운 그 알림일 때만 지우기(자동 알림이 뒤에 온 오류를 지우지 않게) |
| 리셋 키 | 키가 바뀌면 지운다. 패널은 열림 여부 |
| `node` · `inlineNode` | 배너 · 박스 없는 글자(고정 저장바용) |

### 자리 — 그 버튼 근처, 제목은 밀지 않는다

| 화면 형태 | 자리 |
|---|---|
| 페이지 | 페이지 헤더 **바로 아래** |
| 드로어·다이얼로그 | 패널 본문 최상단 |
| 본문에서 제목을 직접 그리는 다이얼로그 | 제목·설명 다음 |
| 화면 안 섹션·탭 | 제목·버튼이 든 헤더 행 다음 |
| 하단 고정 저장바 | `inlineNode` 를 저장 버튼 옆에 |
| 표의 행 안 버튼 | 배너 없음 → 토스트 |

- 자동으로 사라지지 않는다(닫기 버튼). 한 화면에 배너는 하나 — 뒤 메시지가 앞을 대체한다.
- 컴포넌트가 아닌 헬퍼 함수는 배너를 인자로 받는다.

## 토스트 — 공용 토스트 헬퍼

```tsx
// React 예시
pushToast.success('Order created successfully.')
pushToast.apiError(error, 'Failed to delete the order.')   // 표의 행 안 버튼
```

- 모든 성공과 표의 행 안 버튼의 결과에만. 화면에서 토스트 라이브러리를 직접 부르지 않게 린트 경고를 둔다(공용 헬퍼만).
- 지속 시간은 종류와 상관없이 **사용자 설정**을 따른다. 설정이 꺼져 있으면 오류만 뜨고 사용자가 닫는다. 오류를 남겨 두는 것은 배너의 규칙이다.

## 예상 못 한 오류에는 조회용 code

`danger`(5xx·네트워크)일 때만 메시지 아래 `code: <끝 8자리>` + 복사 버튼(복사는 전체 32자).
- 사용자가 캡처를 전달하면 담당자가 그 값으로 로그의 그 요청을 바로 찾는다.
- 이름은 `Trace ID` 가 아니라 `code` — 읽는 사람은 개발자가 아니다.
- 4xx 에는 붙이지 않는다 — 업무 규칙이 거부한 것이라 시스템 장애처럼 읽히게 된다.
- 값은 응답 봉투의 `traceId`. 네트워크 오류는 봉투가 없어 자연히 빠진다.

## 배너는 직전 시도의 결과 — 새 시도가 시작되면 지운다

| 언제 | 남는 것 | 어디서 지우나 |
|---|---|---|
| 재시도가 필드 인라인으로만 답해질 때 | 앞 5xx 배너 + 새 인라인 | 인라인 분기의 return 앞 |
| 재시도가 성공 | 실패 배너 + 성공 토스트 | 성공 토스트 앞 |
| 패널을 닫았다 다시 열 때 | 빈 폼 위 옛 배너 | 열림 여부를 리셋 키로 |
| 다음 시도의 입력(선택·검색조건·탭)을 바꿀 때 | 새 대상 위 옛 결과 | 그 입력 핸들러 |

- 다이얼로그·드로어는 닫아도 마운트가 남아 상태가 되살아난다 — 패널은 예외 없이 리셋 키를 준다.
- **자동으로 도는 mutation(타이핑 미리보기)의 onSuccess 에서는 지우지 않는다** — 기준은 "사용자가 버튼을 눌러 시작한 시도인가".
- **한 컴포넌트에 배너 창구를 둘 두지 않는다** — 서로 못 지워 성공과 실패가 나란히 뜬다.
- 여러 건을 골라 처리하는 화면은 행 단위 결과 표시를 지우는 시점과 배너를 지우는 시점을 같게.

## 조회(로드) 실패는 표가 말한다

- 공용 표 컴포넌트의 오류 입력(예: `error` prop)에 그 로드의 실패를 넘긴다 — 행이 없을 때 "No data" 대신 제목·메시지·code 를 그린다. 장애로 못 불러온 것과 결과가 없는 것은 다른 사실이다.
- 행이 이미 있으면 바꾸지 않는다 — 재조회 실패로 보던 목록을 지우는 쪽이 더 나쁘다.
- 검색 조건 오류(400 필드 오류)는 표에 띄우지 않는다 — 이미 필드 아래에 나간다.
- 401·403 은 제외. 표가 없는 화면은 배너만.
