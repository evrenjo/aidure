## 폼 검증 — 서버가 판정, 화면은 인라인 표시

- 필수·길이·형식을 화면에서 판정하지 않는다. 제출 → 즉시 요청 → 서버 오류 목록(`field` + `message`) → 그 필드 아래 인라인. 스택 팩에 폼 검증 스킬이 있으면 그 절차를 따른다(React 는 `form-validation-pattern`).
- 입력칸이 막아도 되는 것은 **컬럼에 저장될 수 없는 키 입력**뿐 — 최대 길이(컬럼 길이), 숫자 칸의 문자, 소수 자릿수 초과.
- 서버가 `field` 없이 메시지만 주면 배너로 올린다(아무것도 안 띄우면 거부된 저장이 조용히 사라진다).
- 오류 상태는 색만이 아니라 `aria-invalid` 로도. 문구 없는 클라이언트 검증 규칙을 두지 않는다.
- 스키마 검증 라이브러리로 서버 규칙을 화면에 복제하지 않는다 — 규칙이 두 곳이면 갈라진다.
- 검증할 때 입력 가능한 컨트롤마다 **입력 · 미입력 · 초과** 세 케이스. 초과가 500 이면 서버 입력 검증이 빠진 것이다.

## 폼 기본기 (HTML 이 이미 주는 것을 버리지 않는다)

- 새 폼은 입력마다 **보이는 라벨**(기존 화면은 디자인을 바꾸지 않고 `aria-label` 로 이름만). placeholder 는 라벨이 아니다(입력하면 사라진다). 형식 안내·요구사항은 `aria-describedby` 로 필드에 잇는다.
- 맞는 `type`·`inputmode`·`autocomplete` 를 준다 — `email`·`tel`·`url`, 로그인 `username`/`current-password`, 새 비밀번호 `new-password`, 주소·이름 토큰(WCAG 1.3.5). 브라우저 자동완성·비밀번호 관리자가 동작해야 한다.
- 비밀번호·인증 코드 칸에서 **붙여넣기를 막지 않는다**(WCAG 3.3.8). 비밀번호 보기 토글을 둔다. 확인 재입력칸은 꼭 필요할 때만.
- 제출은 진짜 `<form>` + `type="submit"` 버튼(Enter 제출). 동작 이름이 드러나는 라벨("Save order", 단순 "Submit" 지양).
- 같은 흐름에서 이미 받은 값을 다시 입력시키지 않는다 — 미리 채우거나 고르게(WCAG 3.3.7).
- **오류 뒤 입력 보존** — 서버가 거부해도 폼 값은 그대로. 제출 오류가 여럿이면 첫 오류 필드로 포커스를 옮기거나 폼 위 오류 요약(각 필드 링크)을 둔다.
- 입력 중 매 키마다 오류를 띄우지 않는다 — 필드를 떠날 때나 제출 때. 이미 오류가 뜬 필드는 고치는 즉시 지운다(처음엔 기다리고, 오류 뒤엔 즉시).
- 형식 요구(날짜 형식·길이)는 입력 **전에** 보이게 안내한다. 라틴 문자만·한 나라 형식만 받는 검증을 넣지 않는다. 이름은 가능하면 한 칸, 전화·카드 번호를 여러 칸으로 쪼개지 않는다(자동완성이 깨진다).
- 필드 `name`·`id` 는 배포마다 바뀌지 않게 고정한다(자동완성·테스트가 기댄다). 관련 컨트롤 묶음은 `<fieldset>` + `<legend>`.

## 숫자·날짜 표시 — 공용 포맷터

| 유형 | 규칙 |
|---|---|
| 통화 | 기호 + 천단위 구분 + **저장 컬럼 scale 만큼 소수**. 음수 표기(괄호·색)는 표시 컴포넌트 한 곳에서 |
| 원가·계수처럼 scale 이 다른 값 | 포맷터를 따로 둔다 (가격 2자리, 원가 3자리 등) |
| 수량·카운트 | 천단위 구분, 소수 0, 통화 기호 없음 |
| 비율 | 소수 자릿수를 함수로 고정하고 `%` |
| 날짜·시각 | 공용 날짜 포맷터 하나. 기준 시간대를 정해 두고 화면마다 다르게 쓰지 않는다(시간대·로캘 원칙은 frontend 문구·i18n 룰) |
| 식별자(번호·ID·코드) | **포맷하지 않는다** |

- 빈 값은 `-`, 숫자로 못 읽는 값은 원문 그대로. 저장·전송 값은 raw 유지 — 표시에만 적용.
- 화면 안에서 `Intl.NumberFormat` 을 새로 만들거나 `toFixed` + 기호를 이어 붙이지 않는다. 가능하면 린트로 막는다.

## 숫자 입력칸

- 가격·원가·수량 입력은 **공용 숫자 입력 컴포넌트 하나**. 자릿수(정수/소수)는 **필드마다 저장 컬럼 정밀도**로 준다.
- 넘치는 자릿수는 타이핑·붙여넣기 시점에 막는다(반올림하지 않는다). 포커스를 떠나면 0 채움 + 천단위 구분. 입력 중엔 외부 값이 타이핑을 덮지 않는다.
- `type="number"` 를 쓰지 않는다(구분 기호를 못 담는다) — `type="text"` + `inputmode`. 칸 안에 `$`·`%` 를 넣지 않는다. 빈칸은 null(0 과 구분).
- 서버가 두 번째 겹이다 — 저장 요청에 자릿수 검증을 둬서 초과가 500 이 아니라 400 + 필드 인라인이 되게 한다.

## 파일 첨부

- **즉시 업로드 금지** — 파일은 부모 동작(OK/Save/Run) 전까지 화면 상태로만. 취소하면 고아 파일 0.
- 부모 동작 때: 공용 업로드 API → 첨부 그룹 ID → 부모 요청 본문에 그 ID. 소유 엔티티는 그룹 ID 한 컬럼만.
- 조회는 항상 그룹 ID 기준, 정렬 순서 오름차순. 화면별 조건 분기 금지.
- 허용 확장자는 그 파일을 읽는 코드와 짝이다 — 넓히려면 파서와 화면 `accept` 도 함께 고친다.
