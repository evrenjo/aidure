## 기본 정책

권한이 없어 못 쓰는 컨트롤은 **숨기지 않는다. 비활성 + 왜 못 쓰는지 툴팁.** 숨기면 사용자는 "기능이 없다" 와 "내 권한으로 못 쓴다" 를 구분할 수 없고, 관리자는 권한 문제인지 미구현인지 판별할 수 없다. 화면(라우트) 진입 권한은 라우트 가드가 접근 거부 화면으로 처리하므로 이 규칙 대상이 아니다.

**화면 게이팅은 안내다. 인가는 서버가 요청마다 한다** — 비활성·숨김은 개발자 도구로 풀린다. 서버가 막지 않는 동작을 화면만 막고 있으면 그것은 결함이다(OWASP: 접근 통제는 신뢰할 수 있는 서버 쪽 코드에서).

```
canCreate = 권한(메뉴 키, CREATE)
Tooltip(표시 = !canCreate, 문구 = noPermission("create orders"))
  Button(disabled = !canCreate) "Create"
```

- 문구는 **헬퍼 하나**(`noPermission(action)` → `You do not have permission to {action}.`)로만 만든다. 인자는 동사구. 메뉴 코드·권한 타입을 노출하지 않는다.
- 원래 툴팁이 있던 컨트롤은 권한 있을 때 문구를 두고, 없을 때만 사유로 바꾼다. 원래 없던 컨트롤에 잉여 툴팁(동작 이름만 되풀이)을 달지 않는다.
- 권한 외 조건(미저장 변경·잠금·선택 없음)과 함께면 **권한을 앞에** 두고 툴팁도 그 순서로. 가드가 여럿이면 비활성 사유 하나로 모아 버튼을 한 번만 그린다.
- 비활성 버튼은 네이티브 `disabled`(Tab 순서에서 빠진다). 링크·`div` 로 그리면 `aria-disabled` + 핸들러 조기 종료. 툴팁 래퍼가 자식을 감싸는 요소를 둬야 비활성 버튼 위에서도 뜬다.
- 네이티브 `disabled` 는 포커스를 못 받아 **키보드·스크린리더 사용자는 툴팁에 닿지 못한다.** 이유를 모르면 업무를 못 하는 자리(단독 주요 버튼 등)면 이유를 곁에 글자로도 보이거나, `aria-disabled` + 포커스 유지 + `aria-describedby` 로 이유를 잇는다.

## 권한 키 고르기

**버튼이 있는 화면이 아니라 그 버튼이 부르는 엔드포인트가 매핑된 메뉴(권한 단위)의 키.**

- 부모 메뉴 키가 자식 권한의 합산이면 게이팅이 헐거워진다 — 엔드포인트가 매핑된 그 메뉴 키를 쓴다.
- 엔드포인트가 없는 (메뉴, 권한) 조합으로 게이팅하지 않는다 — 부여 화면에 체크박스가 없어 아무도 켤 수 없다.
- **엔드포인트를 다른 메뉴로 옮기면 그 메뉴로 게이팅하던 화면도 같이 고친다.** "그 메뉴가 그 권한을 갖는가" 만 보는 감사는 옛 키가 다른 엔드포인트로 살아 있으면 통과한다.
- 가능하면 프로젝트에 **화면의 권한 키 ↔ 메뉴-엔드포인트 매핑 대조 스크립트**를 두고 새 게이팅마다 돌린다(매핑은 프로젝트 DB·시드마다 달라 팩에는 없다).

## 메뉴에 엔드포인트를 배치하는 원칙

1. **조회 메뉴는 조회, 수정 메뉴가 쓰기를 갖는다.** 수정 화면에만 있는 컨트롤(가져오기·코멘트 저장)은 그 화면 메뉴에. 조회 화면도 쓰는 읽기는 조회 메뉴에 남기고, 수정 화면이 필요하면 양쪽에 매핑한다.
2. **인증만으로 허용되는 전역 메뉴에는 부여 행을 두지 않는다** — 아무 일도 하지 않고 시드 그룹만 갖게 된다.
3. **그룹 저장은 화면이 렌더한 메뉴의 부여만 지운다** — 전량 삭제 후 재삽입하면 화면 트리 밖 부여가 저장 한 번에 사라진다. 시드는 저장의 고정점이어야 한다(저장 왕복 후 diff 0).
4. **메뉴 URL = 라우트 경로와 글자 단위로 같게**, 라우트가 아닌 메뉴(헤더·팝업·패널)는 URL 을 비운다. 다르면 전원이 접근 거부된다.

## 예외 — 숨겨도 되는 것

| 대상 | 이유 |
|---|---|
| 내비게이션 메뉴 항목 | 접근 권한 없는 메뉴는 서버 응답에서 빠진다 |
| 데이터 조회 위젯 자체 | 권한 없는 API 를 부르면 403 알림이 뜬다 — 렌더 자체를 막는다 |
| 탭·섹션 전체 | 안에 쓸 수 있는 것이 하나도 없을 때 |
| 소유권 조건 | "내 것이 아니라 못 고친다" 는 권한이 아니다 |
| 상태상 동작이 성립하지 않음 | 그 상태·버전에 그 동작 자체가 없다 |
| 시스템 최상위 등급 전용 | 그룹 권한이 아니라 등급 조건. 서버도 같은 기준 |
| 요구사항(수용 조건)이 숨김을 명시 | **그 컨트롤에만**, 코드 주석에 티켓 번호 |

권한이 아닌 조건과 섞이면 분리한다 — 소유권·상태는 숨김, **권한만 비활성**.
