## API 연동

- **생성 클라이언트(OpenAPI·GraphQL 코드 생성 등)가 있으면 그것만 쓴다.** 화면에서 HTTP 라이브러리·`fetch` 를 직접 부르지 않는다 — 공통 인증(토큰 갱신)·오류 처리를 우회한다.
- **생성 폴더를 고쳐야 할 것 같으면 백엔드 스펙이 틀린 것이다** — 백엔드의 스키마·설명을 고치고 재생성한다. 생성 폴더는 손으로 고치지 않는다.
- **도메인 파생값은 응답 필드로** — 화면에서 합계·상태·판정을 다시 계산하면 서버와 갈라진다. 화면이 하는 후가공은 표시 형식뿐.
- **오류 코드 분기는 한 곳(공통 요청 계층)** — 로그인 실패 · 토큰 만료 자동 갱신 · 세션 만료 · 화면 권한 없음 → 접근 거부 화면 · API 권한 없음 → 알림 · 네트워크 → 서비스 불가 표시. 화면마다 401·403 을 다시 처리하지 않는다.
- 응답 봉투(예: `{ code, message, data, errors }`)의 모양은 프로젝트마다 다르다. 꺼내는 유틸을 한 곳에 두고 화면마다 새로 짜지 않는다.

## 파일 위치·이름 = 그 파일을 쓰는 곳

| 어디에 두나 | 언제 |
|---|---|
| `{화면 루트}/{도메인}/{모듈}/{화면}/` | 그 화면만 쓴다 |
| `{화면 루트}/{도메인}/{모듈}/shared/` | 그 모듈의 화면들만 쓴다 |
| `{화면 루트}/{도메인}/shared/` | 모듈을 넘어 쓴다 |

- **`shared` 는 자기 범위의 형제(기능) 모듈을 import 하지 않는다** — 방향이 뒤집히면 순환이 된다.
- **한 곳만 쓰는 파일을 `shared` 에 두지 않는다** — 그 소비처로 내린다.
- **공용 파일 맨 위에 소비처 한 줄 주석**(`Used by: …`) — 폴더 이름이 못 하는 말을 한다. 실제 import 와 맞아야 한다.
- **이름 접두어 = 그 파일이 다루는 데이터의 소유자.** 두 소유자가 함께 쓰면 소유자 중립 이름으로.
- **소비처는 화면 루트 전체에서 센다** — 다른 도메인도 공용 파일을 쓴다. 한 도메인 안만 보고 내리면 밖에서 깨진다.
- **새 화면이 남의 폴더에서 가져오게 되면 그때 옮긴다.** 이름이 사실이면 위치만으로 옮기지 않는다.
- JS·TS import 를 읽어 이 배치를 검사하는 도구가 React 스택 팩에 있다(`check-shared-placement.js`). JS·TS 파일로 된 다른 스택도 `--repo` 로 대상을 주면 돌릴 수 있다.

## 레이아웃·표시

- **상세 페이지 고정 바**(상단 정보바·탭바·하단 저장바)는 `position: sticky` 공용 컴포넌트 하나로. `position: fixed` + 사이드바 폭만큼 `left` 계산은 쓰지 않는다 — 사이드바 표시 기준 폭과 어긋나는 구간에 빈칸이 생기고, 최소 폭 아래 가로 스크롤에서 본문을 따라가지 않는다.
- 코드값은 raw 값 + 툴팁 설명으로 표시한다(라벨 단독 금지). 아이콘은 한 세트로 통일한다.
- 스타일은 프로젝트 방식(유틸리티 클래스·CSS 모듈 등)을 따른다. 인라인 스타일은 동적 값(top/left 등)에만.
- 새 공용 컴포넌트를 만들기 전에 디자인 시스템·공용 폴더에 같은 역할이 있는지 먼저 찾는다.
- 디자인 토큰(색·간격·글자 크기 변수)이 있으면 값을 직접 쓰지 않고 토큰을 쓴다. 다크 모드가 있으면 토큰으로 양쪽을 맞춘다.

## 반응형·브라우저 지원

- **좁은 폭에서도 가로 스크롤 없이** — 320 CSS px 폭(= 1280px 화면 400% 확대)에서 내용이 한 방향 스크롤로 읽혀야 한다(WCAG 1.4.10). 표·코드처럼 2차원이 본질인 것만 예외. 앱이 최소 폭을 정해 두었으면 그 기준을 따른다.
- 글자 크기는 사용자 설정·200% 확대를 따라가게 상대 단위(`rem`)로, 고정 높이 상자에 글자를 가두지 않는다(잘린다).
- 지원 브라우저 목록(browserslist 등)이 있으면 그 범위의 기능만 쓰고, 벗어나는 기능은 기능 감지 + 대체 동작으로(점진적 향상). 핵심 동작이 최신 기능에만 기대지 않게 한다.

## 패키지 추가

- 새 패키지는 먼저 묻는다. 플랫폼 API·이미 있는 의존성으로 되는지, 실제 이름·유지 상태·크기를 확인한 뒤(보안·성능 룰).
- 잠금파일이 가리키는 관리자로만 추가한다(잠금파일이 둘이면 둘 다 맞게). 커밋 전 CI 와 같은 고정 설치(`npm ci` · `pnpm install --frozen-lockfile` · `yarn install --immutable` · `bun install --frozen-lockfile`)로 확인한다.
- 정상적인 추가는 잠금파일에 그 패키지 줄만 늘어난다. 잠금파일 형식 버전이 바뀌거나 diff 가 그보다 크면 커밋하지 말고 보고한다.
