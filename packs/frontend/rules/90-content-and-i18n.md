## 문구

- **프로젝트의 문구 규칙·용어집을 먼저 따른다.** 같은 대상은 화면마다 같은 단어로(Delete ↔ Remove 섞지 않기). 버튼은 동작을 말한다("Save changes", 단순 "OK" 지양 — 확인창 기본 라벨 규칙은 피드백 룰).
- 사용자 말로 쓴다 — 내부 코드·테이블명·권한 키·예외 이름을 문구에 노출하지 않는다.
- 장식용 대시(`—`·`–`)를 넣지 않고 마침표·쉼표로 끊는다(좁은 툴팁에서 줄 끝에 대시만 남는다). 요청받은 곳만 예외.
- 빈 상태 문구는 "없다" 로 끝나지 않고 다음 행동을 안내한다(검색 조건 바꾸기·새로 만들기). 오류 문구 원칙은 frontend 피드백 룰.

## i18n 이 있는 프로젝트

- **사용자에게 보이는 문자열을 코드에 하드코딩하지 않는다** — 번역 키로. `alt`·`aria-label`·`title`·placeholder·토스트·확인창 문구도 포함된다.
- **문장을 조각으로 이어 붙이지 않는다** — `"Deleted " + n + " items"` 대신 자리표시자가 있는 한 문장 메시지. 어순은 언어마다 다르다.
- 번역 문자열에 HTML 을 넣어 `innerHTML` 로 그리지 않는다 — 라이브러리의 태그 보간을 쓴다(XSS 경로).
- 사용자 값(이름·주소)은 번역하지 않는다. 번역할 문구와 구분한다.
- 복수형은 i18n 라이브러리의 복수 규칙(ICU MessageFormat·`Intl.PluralRules`)으로. `n === 1 ? … : …` 로 영어 규칙을 하드코딩하지 않는다.
- 새 키는 프로젝트가 정한 기본 로캘 파일에 넣고, 다른 로캘을 비워 두는 방식(대체 언어)은 프로젝트 관례를 따른다. 키 이름 규칙을 지킨다.
- 번역으로 길어질 수 있게 버튼·라벨 폭을 고정하지 않는다. 오른쪽→왼쪽 언어를 지원하면 방향은 CSS 가 아니라 마크업(`<html dir>`)으로, 스타일은 `left`/`right` 대신 논리 속성(`margin-inline-start`), 사용자 입력칸은 `dir="auto"`, 섞인 방향의 사용자 값은 `<bdi>`.
- i18n 이 없는 프로젝트에 i18n 을 새로 들이는 것은 묻는다. 그 전까지는 문구를 한 곳(상수 모듈)에 모아 두는 정도로.

## 로캘·숫자·날짜

- 표시 형식은 공용 포맷터(frontend 폼·입력 룰)로만. 포맷터 안에서는 `Intl.NumberFormat`·`Intl.DateTimeFormat`·`Intl.RelativeTimeFormat` 에 **프로젝트가 정한 로캘**을 넘긴다 — 로캘을 비워 브라우저 기본값에 맡기면 사용자마다 형식이 갈린다(단일 로캘 앱이면 그 로캘을 고정).
- 문서 언어 `<html lang>` 을 실제 언어와 맞춘다. 다른 언어 구간은 그 요소에 `lang`.
- 정렬·비교는 로캘 비교(`Intl.Collator`·`localeCompare`)로. 이름·주소 입력을 한 나라 형식(성/이름 분리 필수, 우편번호 형식)으로 가정하지 않는다.

## 시간대

- 서버와 주고받는 시각은 **시간대가 붙은 값(UTC 또는 오프셋 포함 ISO 8601)**. 시간대 없는 문자열을 로컬 시각으로 파싱하지 않는다.
- 표시 기준 시간대(사용자·업무 지역·서버)를 프로젝트가 정한 하나로 쓰고, 필요하면 시간대 약어를 함께 보인다. 시간대는 IANA ID(`America/New_York`)로 다룬다.
- **생일·마감일처럼 날짜만 뜻하는 값**은 시각으로 바꾸지 않는다 — 시간대 변환에 하루가 밀린다.
- 날짜 선택기의 값과 서버 전송 값의 형식을 한 유틸에서 변환한다.
