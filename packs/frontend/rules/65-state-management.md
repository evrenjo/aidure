## 상태마다 주인이 하나

| 종류 | 주인 | 예 |
|---|---|---|
| 서버 데이터 | **서버 상태 캐시**(프로젝트의 데이터 조회 라이브러리 · 생성 클라이언트) | 목록·상세·코드값 |
| 화면을 재현하는 값 | **URL** (frontend URL 상태 룰) | 페이지·정렬·검색·필터·탭 |
| 폼 편집 중 값 | 폼 (컴포넌트 · 폼 라이브러리) | 저장 전 입력 |
| 한 컴포넌트의 UI 상태 | 그 컴포넌트 | 펼침·호버·다이얼로그 열림 |
| 앱 전체 UI 상태 | 전역 스토어 하나 | 테마·사이드바 접힘·로그인 사용자 |

- **서버 응답을 전역 스토어·컴포넌트 상태에 복사하지 않는다** — 캐시와 사본이 갈라진다. 서버 데이터를 캐시로 옮기면 남는 전역 상태는 대개 아주 적다.
- 가장 가까운 곳에 둔다 — 컴포넌트 → 공통 부모 → URL → 전역 순으로, 필요할 때만 올린다.
- **다른 상태에서 계산되는 값은 상태로 두지 않는다** — 렌더 때 계산한다(합계·필터된 목록·"전체 선택됨").
- **모순될 수 있는 불리언을 여럿 두지 않는다** — `isLoading`·`isError`·`isSuccess` 대신 상태 하나(`'idle' | 'loading' | 'error' | 'success'`).
- 같은 데이터를 두 곳에 들고 있지 않는다 — 선택된 항목은 객체가 아니라 ID 로 들고 목록에서 찾는다.
- 깊게 중첩된 상태보다 평평하게(ID → 항목 맵).

## 서버 데이터 갱신

- 저장·삭제가 성공하면 **그 데이터를 쓰는 캐시를 무효화**(재조회)한다. 응답으로 캐시를 직접 고치는 것은 응답이 전체 항목을 줄 때만.
- 낙관적 갱신은 실패 시 되돌림과 오류 표시를 함께 구현할 때만. 되돌릴 수 없는 동작(삭제·결제)에는 쓰지 않는다.
- 늦게 도착한 옛 응답이 새 결과를 덮지 않게 한다(요청 취소·쿼리 키로 구분).
- 로그아웃·사용자 전환 때 캐시와 전역 스토어를 비운다.

## 폼 상태

- 편집 중인 값은 저장 전까지 폼이 가진다. 서버 데이터가 다시 와도 **사용자가 고치고 있는 값을 덮지 않는다**(입력 중 외부 갱신 금지).
- 미저장 변경이 있으면 이탈 시 확인(frontend 피드백 룰의 "변경 폐기" 다이얼로그).
- 저장 실패 뒤에도 폼 값은 그대로 둔다.

## 저장소

- `localStorage` 등 브라우저 저장소에는 사용자 편의 설정(표 열 너비·접힘)만. 토큰·개인정보는 두지 않는다(frontend 보안 룰). 읽을 때 값이 없거나 깨졌을 수 있다고 보고 기본값으로 돌아간다.
