## 로딩 — 그 자리에 이전 내용이 있는가

| 상황 | 표시 |
|---|---|
| 첫 조회 · 탭 전환 | 스켈레톤 |
| 페이지 이동 · 정렬/필터 변경 · 재검색 | **직전 내용 유지 + 오버레이** (스켈레톤이면 페이지가 짧아져 스크롤이 튄다) |
| 무한 스크롤로 덧붙이는 새 자리 | 그 자리에만 스켈레톤 |
| 저장·삭제 등 블로킹 동작 | 버튼 스피너 |

- **기다림에 맞는 표시** — 약 1초 안이면 결과만 보여도 되고, 몇 초 걸리면 진행 중 표시, 10초를 넘기면 진행률(가능하면 %)과 취소 수단을 준다. 반복되는 짧은 요청마다 스피너를 번쩍이지 않는다.
- 진행 중인 동작의 버튼은 중복 제출을 막는다(대기 중 비활성 또는 두 번째 클릭 무시).
- `"Loading..."` 텍스트를 쓰지 않는다(앱 초기화 화면 제외). 공용 표 컴포넌트가 직전 행 유지를 스스로 하게 만든다.
- 빈 상태 판정은 로딩과 함께 본다 — "로딩 중이 아니고 0건" 일 때만 빈 상태.

## 빈 결과와 조회 실패는 그 자리에서 구분

- 조회(로드) 실패는 표·목록이 그 자리에서 말한다 — "데이터 없음" 대신 제목·메시지·조회용 코드. 장애로 못 불러온 것과 결과가 없는 것은 다른 사실이다.
- 행이 이미 있으면 바꾸지 않는다(재조회 실패로 보던 목록을 지우지 않는다). 검색 조건 400 은 필드가 말하므로 표에 띄우지 않는다.

## 오류 문구 — 무슨 일인지, 어떻게 고치는지

- 사용자 말로 **무엇이 일어났는지 + 무엇을 하면 되는지**를 쓴다. "Invalid input"·"Error occurred" 같은 일반 문구, 스택·SQL·내부 코드 원문, 사용자를 탓하는 어조를 쓰지 않는다.
- 원인 자리 가까이에 둔다(필드 오류는 필드 아래, 동작 오류는 그 버튼 곁). 색만으로 알리지 않고 아이콘·글자를 함께.
- 오류 뒤에도 사용자가 넣은 값·선택·스크롤 위치를 그대로 둔다. 다시 하게 할 때는 같은 입력을 또 받지 않는다.

## 알림 — 버튼 곁에, 성공은 토스트

| 버튼이 어디 있나 / 무엇인가 | 표시 |
|---|---|
| 페이지·섹션 헤더, 폼 | 배너 — 헤더 행 **아래**(제목을 밀지 않게) |
| 드로어·다이얼로그 안 | 배너 — 패널 본문 상단 |
| 하단 고정 저장바 | 버튼 옆 한 줄 글자 |
| 표의 **행 안** 버튼 | 토스트 (배너 자리가 화면 밖이고, 끌어올리면 보던 행을 잃는다) |
| **성공** | 예외 없이 토스트 (가능하면 배너 타입에서 success 를 빼 타입 검사로 막는다) |
| 입력값 오류 | 필드 아래 인라인. 필드가 특정 안 되는 것만 배너 |
| 되돌릴 수 없는 확인 | 확인 다이얼로그 |

- 배너는 **직전 시도의 결과**다 — 새 시도(재제출·성공·입력 대상 변경)가 시작되면 지운다. 패널은 닫아도 상태가 남는 구현이 많으므로 열림 여부로 리셋한다. 자동으로 도는 미리보기 요청에서는 지우지 않는다. 한 컴포넌트에 배너 창구를 둘 두지 않는다.
- 5xx·네트워크 오류에는 **조회용 추적 코드**(응답의 추적 ID 끝 8자리, 복사는 전체)를 붙인다. 4xx 에는 붙이지 않는다. 401·403 은 공통 처리 몫이라 화면에서 띄우지 않는다.
- 토스트 시간은 종류와 상관없이 사용자 설정을 따른다. 오류를 남겨 두는 것은 배너의 규칙이다.
- **보조기기에 알린다** — 토스트·배너·"저장됨"·"결과 N건" 같은 상태 메시지는 포커스를 옮기지 않고 읽히게 `role="status"`(정보) / `role="alert"`(오류) 또는 `aria-live` 영역으로(WCAG 4.1.3). 라이브 영역은 처음부터 DOM 에 두고 내용만 바꾼다.
- 사라지는 토스트에 사용자가 **해야 할 일**(재시도 링크 등)을 담지 않는다 — 조치가 필요한 오류는 남는 배너로.

## 확인창 — 되돌릴 수 없는 동작만

- 대상: Delete · Remove · Revoke · Discard · Reject · Lock, 외부 통지를 유발하는 변경. 저장·등록·제출·승인은 **즉시 실행**.
- 프로젝트의 공용 확인 다이얼로그 하나만. 버튼 클릭은 다이얼로그를 **열기만**, 실제 요청은 확인 핸들러에서.
- 제목 `{Action} {Entity}?`, 본문은 의문문 한 줄 + 대상 식별자 강조, 파괴 동작은 빨간 확인 버튼 + "This action cannot be undone." 버튼 라벨은 기본(`OK`/`Cancel`) — 바꾸는 예외는 문서에 먼저 등록한다.
- Cancel·X·ESC·백드롭은 모두 닫기만. 폼 상태는 유지. 파괴 동작 확인창은 열릴 때 **덜 파괴적인 버튼(Cancel)에 포커스**(Enter 연타로 지워지지 않게), 닫히면 연 버튼으로 포커스를 돌린다.
- 법적·금전·데이터 삭제처럼 되돌리기 어려운 제출은 확인·검토·되돌리기 중 하나를 준다(WCAG 3.3.4). 확인창 대신 되돌리기(Undo)가 가능한 동작이면 그쪽이 흐름을 덜 끊는다 — 프로젝트 관례를 따른다.
- 표의 인라인 행 삭제도 확인창을 거친다. 미저장 이탈은 공용 "변경 폐기" 다이얼로그.
- 요구사항이 확인 단계를 못박은 컨트롤만 예외로 넣고 주석에 티켓 번호. 다른 저장으로 일반화하지 않는다.

## 모달·스크롤

- 표·목록이 들어가는 다이얼로그는 제목을 고정 헤더 영역에 둔다(본문만 스크롤). 긴 본문은 모달 안에서 스크롤.
- 레이아웃이 내부 스크롤 컨테이너를 쓰면 `window.scrollTo`·`window.scrollY` 는 조용히 무의미해진다 — 컨테이너 기준 유틸을 쓴다.
