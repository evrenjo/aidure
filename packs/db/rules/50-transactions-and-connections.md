## 트랜잭션 · 잠금 · 동시성 · 커넥션

### 1. 트랜잭션은 짧게

- 트랜잭션 안에서 **외부 호출(HTTP·메시지 발행·파일 업로드)·사용자 입력 대기·긴 계산**을 하지 않는다. 잠금을 쥔 채 기다리게 되고, 롤백돼도 외부 효과는 남는다.
- 외부 효과는 커밋 **뒤에** 한다. 커밋과 외부 발행을 함께 보장해야 하면 같은 트랜잭션에 "보낼 일" 행을 쓰고 커밋 뒤 따로 보낸다(outbox 류) — 프로젝트에 방식이 있으면 그것을 따른다.
- 대량 작업은 한 트랜잭션이 아니라 묶음마다 커밋한다(`packs/db/rules/30-data-change.md`).
- 열어 두고 잊은 트랜잭션(유휴 상태로 잠금 보유)이 없게 한다. 조회 도구로 DB 에 붙었다면 작업이 끝나면 커밋·롤백하고 끊는다.

### 2. 격리 수준 — 기본값은 DBMS 마다 다르다

| DBMS | 기본 | 주의 |
|---|---|---|
| PostgreSQL | READ COMMITTED | 문장마다 새 스냅샷. 읽고 나서 쓰는 코드는 갱신 유실 가능 |
| MySQL·MariaDB (InnoDB) | REPEATABLE READ | 잠금 읽기·UPDATE·DELETE 가 범위(갭) 잠금을 잡아 교착이 잦아질 수 있다 |
| SQL Server | READ COMMITTED (잠금 방식) | 스냅샷 방식(`READ_COMMITTED_SNAPSHOT`)은 DB 설정. Azure SQL 은 기본 켜짐 |
| Oracle | READ COMMITTED | 읽기는 잠그지 않는다 |

- **읽고 → 계산하고 → 쓰는** 코드(잔액·재고·순번·상태 전이)는 갱신 유실을 막는다: 원자적 UPDATE(`SET x = x - 1 WHERE … AND x > 0`), 행 잠금(`SELECT … FOR UPDATE`), 또는 버전 컬럼(낙관적 잠금) 중 프로젝트가 쓰는 방식을 따른다.
- 격리 수준을 올리면(REPEATABLE READ·SERIALIZABLE·SNAPSHOT) **직렬화 실패 오류가 정상 동작의 일부**가 된다. 그 트랜잭션 전체를 다시 시도하는 코드가 있어야 한다.
- 격리 수준을 바꾸는 것은 앱 전체 동작을 바꾼다 — 사용자에게 묻는다.

### 3. 교착 · 잠금 대기

- 여러 행·테이블을 바꿀 때는 **모든 코드 경로에서 같은 순서로** 잠근다(예: id 오름차순, 부모 → 자식).
- 교착은 DBMS 가 한쪽을 끊어 풀어 준다. **끊긴 쪽을 다시 시도하는 코드**를 둔다(재시도는 몇 번으로 제한, 사이에 잠깐 대기). 재시도되는 트랜잭션은 **다시 돌려도 안전하게**(멱등) 짠다.
- 인덱스가 없으면 UPDATE/DELETE·외래키 검사가 더 많은 행을 훑고 더 많이 잠근다. 교착·잠금 대기를 조사할 때 실행 계획과 외래키 컬럼 인덱스부터 본다.
- 조사할 때는 DBMS 의 잠금·교착 기록(잠금 뷰·교착 로그)으로 **실제 충돌한 문장**을 확인한다. 추측으로 격리 수준·잠금 힌트를 바꾸지 않는다.
- 앱 쿼리에도 문장 실행 제한·잠금 대기 제한을 둔다(설정 위치는 드라이버·ORM·DB 역할마다 다르다). 무한 대기보다 빨리 실패하는 편이 낫다.

### 4. 커넥션 풀

- 풀 크기는 크다고 빠르지 않다. DB 가 실제로 동시에 처리할 수 있는 수(대략 CPU 코어 수의 몇 배)에 맞춰 **작게** 시작하고 재서 조절한다.
- **전체 커넥션 수 = 풀 크기 × 인스턴스 수(오토스케일 최대치 포함) + 배치·관리 도구.** 이 합이 DB 최대 커넥션 수 안에 들어야 한다. 인스턴스를 늘리기 전에 이 계산부터 한다.
- 한 요청이 커넥션을 두 개 이상 동시에 쥐면(중첩 트랜잭션·별도 트랜잭션 호출) 풀이 모자랄 때 **스스로 교착**한다. 그런 경로가 있으면 풀 크기에 반영하거나 구조를 바꾼다.
- 트랜잭션 단위로 커넥션을 돌려쓰는 풀러(PgBouncer transaction 모드, 일부 프록시) 뒤에서는 **세션 상태(SET·세션 잠금·명시적 PREPARE·임시 테이블·LISTEN)가 다음 트랜잭션에 이어지지 않는다.** 풀러가 있는지 먼저 확인한다.
- 커넥션 누수(반납 안 됨)는 코드 경로별로 닫힘을 보장하는 구문(try-with-resources·using·context manager)으로 막는다.

### 5. 시간대

- 시점(이벤트가 일어난 순간)은 **시간대가 붙은 형식이나 UTC 로** 저장한다. 저장 형식이 시간대를 모르면 어느 기준인지 컬럼 코멘트에 적는다.
- DB 세션 시간대·앱 서버 시간대·드라이버 설정이 다르면 같은 값이 다르게 읽힌다. 시간이 어긋나 보이면 **세 곳의 설정부터** 확인한다.
- 사용자에게 보여 줄 때 변환한다. 일광 절약 시간이 있는 지역은 고정 오프셋(`+09:00`, `EST`)이 아니라 **지역 이름**(`Asia/Seoul`, `America/New_York`)으로 변환한다.
- 날짜 범위는 **닫힌-열린 구간**(`>= 시작 AND < 다음날 시작`)으로 쓴다. `BETWEEN` 은 끝 경계를 두 번 셀 수 있다.
- 달력 날짜(생일·마감일)처럼 시점이 아닌 값은 날짜 형식으로 저장하고 시간대 변환을 하지 않는다.
