**보안 장치는 직접 만들지 않는다** — 인증·세션·암호화·토큰 검증은 프레임워크·검증된 라이브러리와 프로젝트에 이미 있는 구성을 쓴다.
보안 설정을 느슨하게 하는 변경(검사 끄기·허용 범위 넓히기·예외 경로 추가)은 **사람 승인** 뒤에만. 세부 값·표는 `packs/backend/docs/security-reference.md`.

## 1. 인가

- **기본 거부** — 새 엔드포인트가 인가 설정 없이 열리지 않게 한다. 공개 경로는 목록으로 명시한다.
- 판정은 **서버에서, 요청마다** — 클라이언트가 보낸 역할·소유자·가격 값을 믿지 않는다. 인증된 주체(토큰·세션)로 판정한다.
- **객체 단위** — ID 가 들어오는 모든 경로에서 소유·권한을 확인한다. 추측하기 어려운 ID(UUID)는 보조일 뿐 인가를 대신하지 않는다.
- **한 곳에 모은다** — 인가 판정은 공용 헬퍼·정책·미들웨어로, 새 엔드포인트는 그것을 쓴다. 엔드포인트마다 다시 짜면 빠진다.
- 파일 저장소·정적 경로의 비공개 파일도 같은 인가를 거친다(추측 가능한 공개 URL 로 내보내지 않는다).
- 인가 실패는 정보를 흘리지 않는 응답으로 끝내고, 로그를 남긴다(반복 실패는 탐지 대상).
- 인가 규칙에는 **거부 케이스 테스트**를 둔다 (「백엔드 테스트」).

## 2. 인증·세션·토큰

- 비밀번호는 **느린 전용 해시**(Argon2id·scrypt·bcrypt·PBKDF2 — 프로젝트 구성)로만 저장한다. 암호화·일반 해시(SHA-256 등)로 저장하지 않는다.
- 로그인·가입·비밀번호 재설정의 실패 응답은 **계정 존재 여부를 드러내지 않는다**(같은 문구, 비슷한 응답 시간).
- 로그인·재설정·OTP 는 **계정 기준** 시도 한도(잠금·지연)를 둔다. IP 기준만으로는 분산 시도를 못 막는다.
- 비밀번호 변경·이메일 변경·고위험 거래는 **재인증**을 요구하는 기존 흐름을 따른다.
- 토큰 검증: 서명(알고리즘은 **서버 설정**으로 고정, `none` 거부)·만료·발급자·대상을 모두 본다. 토큰 헤더가 말하는 알고리즘을 믿지 않는다.
- 로그아웃·비밀번호 변경 시 서버 세션·리프레시 토큰을 무효화한다. 접근 토큰은 짧게.
- 토큰·세션 ID·API 키를 **URL(쿼리)에 싣지 않는다** — 로그·리퍼러·기록에 남는다. 헤더나 본문으로.

## 3. 브라우저가 부르는 API

- **CSRF** — 쿠키로 인증하는 API 의 상태 변경 요청에는 프레임워크의 CSRF 방어(토큰·`SameSite`·Origin/Fetch Metadata 확인)가 걸려 있어야 한다. 헤더 토큰(Bearer)만 쓰는 API 는 대상이 아니다. 상태 변경을 GET 으로 만들지 않는다.
- **CORS** — 허용 출처는 **명시 목록**. 요청의 `Origin` 을 그대로 되돌려 주지 않는다. 자격 증명(쿠키)을 허용하면 `*` 를 쓸 수 없다. 출처별로 응답이 다르면 `Vary: Origin`.
- **쿠키** — 세션 쿠키는 `Secure`·`HttpOnly`·`SameSite`.
- **응답 헤더** — `Content-Type` 을 정확히, `X-Content-Type-Options: nosniff`, 민감 응답은 `Cache-Control: no-store`. 공통 필터에 이미 있으면 그대로 두고 새 경로가 그 필터를 거치는지 본다.

## 4. 요청 한도·자원

- 요청 본문·업로드·배열·페이지 크기에 상한. 넘으면 413·400.
- 비싼 작업(검색·보고서·내보내기·외부 발송·메일)은 **인증 뒤에만**, 사용자별 호출 한도. 초과는 429 + `Retry-After`.
- 사용자 입력이 반복 횟수·할당 크기·재귀 깊이·정규식 길이를 직접 정하지 않게 한다.
- 한도 구현은 게이트웨이·기존 미들웨어가 있으면 그것을 쓴다. 인스턴스가 여럿이면 인메모리 카운터는 인스턴스마다 따로다.

## 5. 비밀값

- 비밀값(키·비밀번호·토큰·연결 문자열)은 **코드·설정 파일 기본값·컨테이너 이미지·테스트·커밋·로그·오류 응답**에 두지 않는다.
- 런타임에 주입받는다 — 프로젝트의 방식(비밀 저장소·마운트 파일·환경 변수)을 따른다. 환경 변수는 프로세스 덤프·로그에 새기 쉬우므로 이를 출력하는 코드를 만들지 않는다.
- 명령줄 인자에 비밀을 넣지 않는다(프로세스 목록·셸 이력에 남는다).
- **실수로 커밋·로그에 나갔으면** 지우는 것으로 끝나지 않는다 — 폐기·교체(rotate)가 필요하다고 즉시 사람에게 알린다. 이력 재작성은 사람이 정한다.
- 비밀 탐지 훅·스캐너가 있으면 끄거나 우회하지 않는다.

## 6. 외부 입력이 닿는 곳

| 입력이 가는 곳 | 규칙 |
|---|---|
| SQL | 파라미터 바인딩. 식별자(정렬 컬럼·테이블)는 허용 목록 (「백엔드 데이터 접근」) |
| OS 명령 | 셸을 거치지 않는 API + 인자 배열. 사용자 값으로 명령 문자열을 만들지 않는다 |
| 파일 경로 | 사용자 값으로 경로를 만들지 않는다. ID → 서버가 아는 경로. 불가피하면 정규화 뒤 허용 디렉터리 안인지 확인 |
| 서버가 대신 부르는 URL (웹훅·이미지 가져오기·미리보기) | 전체 URL 을 받지 말고 허용 목록(스킴·호스트·포트)에서. 이름 해석 뒤 사설·루프백·링크 로컬·메타데이터 주소 차단, 리다이렉트 따라가지 않기 (SSRF) |
| HTML·템플릿 | 템플릿 엔진의 자동 이스케이프. 사용자 값을 템플릿 소스로 쓰지 않는다 |
| CSV·엑셀 내보내기 | `=`·`+`·`-`·`@`·탭·CR 로 시작하는 셀을 무력화 (수식 주입) |
| XML | 외부 엔티티(XXE)·DTD 처리 끈 파서 |
| 역직렬화 | 신뢰할 수 없는 데이터를 언어 고유 직렬화나 다형성 자동 타입으로 풀지 않는다. 명시한 DTO·JSON 으로만 |
| 정규식 | 사용자 입력으로 정규식을 만들지 않는다. 긴 입력에 역추적이 폭발하는 패턴(중첩 반복)을 쓰지 않는다 |
| 로그 | 줄바꿈 제거 또는 구조화 필드로 (「백엔드 로깅 원칙」) |
| 외부 API 응답 | 사용자 입력과 같게 검증한다. 신뢰하는 상대라도 형식·크기·리다이렉트를 확인 |

## 7. 파일 업로드·다운로드

- 인증·인가 뒤에만 업로드. 크기 상한.
- 확장자 **허용 목록** + 내용 검사(시그니처). `Content-Type` 헤더만 믿지 않는다.
- 저장 이름은 서버가 만든다(무작위 ID). 원래 이름은 표시용 메타데이터로만, 길이·문자 제한.
- 웹 루트 밖(또는 별도 저장소)에 저장, 실행 권한 없이.
- 다운로드는 인가 확인 뒤, 서버가 정한 `Content-Type` + `Content-Disposition: attachment`.
- 악성코드 검사·무해화가 프로젝트에 있으면 새 업로드 경로도 그것을 거친다.

## 8. 운영·관리 엔드포인트

- 관리·진단·메트릭·디버그 엔드포인트를 공개 경로로 열지 않는다. 기존 분리(별도 포트·내부망·강한 인증)를 따른다.
- 디버그 모드·상세 오류 페이지·기본 계정·예제 엔드포인트를 운영 설정에 남기지 않는다.

## 9. 의존성 (공급망)

- 새 라이브러리는 필요한지 먼저 본다 — 이미 있는 의존성·표준 라이브러리로 되면 들이지 않는다.
- 들일 때: 공식 저장소, 유지되는 패키지, **이름 철자 확인**(오타 스쿼팅), 버전 고정, **잠금 파일 함께 갱신**.
- "최신이니까" 올리지 않는다 — 필요할 때 의도해서 올린다. 올렸으면 변경 로그의 깨지는 변경을 확인한다.
- 의존성 추가·제거·버전 변경은 보고에 적는다. 쓰지 않게 된 의존성은 뺀다.
