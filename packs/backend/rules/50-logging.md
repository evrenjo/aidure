## 레벨

| 레벨 | 언제 |
|---|---|
| ERROR | 시스템 결함 — 코드 버그·외부 장애·정의하지 않은 5xx. 사람이 봐야 한다 |
| WARN | 업무 거부·입력 오류·404 등 4xx, 재시도로 넘어간 일시 장애 |
| INFO | 정상 이벤트 — 로그인·생성/수정/삭제·배치 시작/끝 |
| DEBUG | 개발 진단 (운영 비활성) |

## 원칙

- **프로젝트 로그 형식을 먼저 찾는다** — 메시지 접두어(오류 코드·도메인), 로그 헬퍼, 구조화 필드 이름. 있으면 그대로 쓰고 새 형식을 만들지 않는다.
- **구조화** — 값은 로거의 치환 인자·필드로 넘긴다. 문자열 연결은 레벨이 꺼져도 문자열을 만들고 필드 추출을 깬다. 메시지 문장은 고정, 바뀌는 값은 필드.
- **한 오류는 한 번만 기록한다** — 잡아서 로그 남기고 다시 던지면 위에서 또 찍힌다. 기록은 최종 처리 지점(대개 전역 오류 처리기)에서.
- **예외를 기록할 땐 예외 객체째** 넘긴다 — 메시지만 넘기면 스택트레이스가 없다.
- **표준 출력·스택 직접 출력 금지** — 로거만. 앱은 로그를 표준 출력 스트림으로 내보내고 파일 위치·회전은 실행 환경이 정하는 경우가 많다 — 기존 설정을 따른다.
- **추적 ID** — 요청마다 추적(trace/correlation) ID 를 로그 컨텍스트에 싣는다. 이미 있으면 그 방식(키 이름·필터)을 쓴다.
  - 들어온 요청의 추적 헤더(W3C `traceparent` 등)는 이어 쓰되 **외부 입력으로 취급**한다 — 형식·길이를 확인하고, 신뢰 경계(공개 인터넷)에서는 새로 시작할 수 있다.
  - 외부 호출·메시지 발행에 추적 컨텍스트를 넘긴다. 배경 작업·메시지 소비도 작업 단위 ID 를 싣는다.
  - OpenTelemetry 를 쓰면 로거 연동(appender·bridge)으로 로그에 trace/span ID 가 자동으로 붙게 한다 — 손으로 필드를 복사하지 않는다.
  - 오류 응답에 그 ID 가 나가면 사용자가 전달한 값으로 로그를 바로 찾는다.
  - 추적 헤더·배지(baggage)에 개인정보·비밀을 싣지 않는다.
- **로그 주입 방지** — 사용자 입력을 메시지 문장에 섞지 않고 필드로 넘긴다. 줄바꿈이 섞인 값이 가짜 로그 줄을 만들 수 있다.
- 오류 코드를 로그에 싣는 프로젝트면 코드는 한 곳(열거형 등)에서 정의하고 문자열 리터럴로 흩어 쓰지 않는다.

## 보안 이벤트

- 로그인 실패·잠금, 권한 거부(403), 입력 검증 실패가 몰리는 것, 관리 기능 사용, 권한·설정 변경은 **누가·언제·무엇을·결과**로 남긴다. 감사 로그 체계가 있으면 그것으로.
- 한 이벤트는 **언제·어디서(서비스·버전·엔드포인트)·누가(사용자 ID·출처)·무엇을(동작·대상·결과·사유)** 을 필드로.
- 로그를 남기는 것만으로 끝이 아니다 — 알림이 걸리는 로그 형식(레벨·코드)이 있으면 맞춘다.
- 외부 호출의 재시도·서킷 브레이커 상태 전환·요청 한도 초과도 남긴다(장애 때 무엇이 먼저 무너졌는지 보인다).

## 개인정보·비밀

| 항목 | 정책 |
|---|---|
| 비밀번호·토큰·세션 ID·API 키·연결 문자열 | 절대 금지 (요청 로깅 필터의 마스킹 목록에도) |
| 주민·여권번호·카드번호·계좌·주소 | 금지 |
| 이메일·전화·이름 | 마스킹, 꼭 필요할 때만 |
| 내부 사용자 ID·요청 ID | 가능 |

- 요청·응답 본문을 통째로 로그에 남기지 않는다. 필요하면 허용 필드만.
