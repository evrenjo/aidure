프로젝트가 이미 다른 구조를 쓰면 **그 구조가 우선**이다. 이 표에 맞추려고 기존 코드를 옮기거나 두 구조를 섞지 않는다.

## 계층

| 계층 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 진입점 (컨트롤러·라우터·핸들러·메시지 소비자) | 요청 해석, 인증 주체 꺼내기, 입력 검증 연결, 서비스 호출, 응답 변환 | 업무 규칙·분기, DB 직접 접근, 트랜잭션 |
| 서비스 (유스케이스) | 업무 규칙, **인가 판정**, 트랜잭션 경계, 여러 저장소 조합 | HTTP 개념(상태 코드·헤더)에 의존 |
| 데이터 접근 (리포지토리·쿼리·DAO) | 조회·저장 | 업무 판정, 커밋 결정, 다른 도메인 규칙 |

- **입력·출력 모델을 저장 모델과 분리한다** — 요청 객체 → 서비스 → 저장 모델, 저장 모델 → 응답 객체. 저장 모델을 그대로 받으면 클라이언트가 보낸 필드가 권한 없이 저장되고(대량 할당), 그대로 내보내면 컬럼 추가가 곧 API 변경·정보 노출이 된다.
- **ORM·DB 세션은 데이터 접근 계층 안에** — 서비스·진입점에서 쿼리 빌더를 직접 조립하지 않는다.
- 한 도메인은 **모든 계층에서 같은 폴더(모듈)명**을 쓴다. 약어 폴더를 만들지 않는다.
- 요청 처리와 실행 골격이 다른 것(배치 잡·메시지 소비자·스케줄 작업)은 최상위에서 역할로 가른다.

## 트랜잭션 경계

- 경계는 **유스케이스(서비스) 한 번 = 트랜잭션 한 번**. 데이터 접근 함수는 스스로 커밋하지 않고, 호출자의 트랜잭션에 참여한다.
- 쓰는 프레임워크가 **어떤 오류에 롤백하고 어떤 오류에 커밋하는지** 알고 쓴다 — 오류를 돌려주면서 앞 단계 변경이 커밋되면 결함이다.
- 트랜잭션 안에서 **외부 HTTP·메시지 발행·파일 I/O 를 기다리지 않는다** — 잠금을 오래 잡고, 롤백돼도 외부 효과는 남는다. DB 커밋과 메시지 발행을 함께 보장해야 하면 아웃박스(같은 트랜잭션에 발행 예정 행 저장 → 별도 발행) 같은 기존 방식을 찾는다.
- 읽기 전용 경로는 읽기 전용으로 표시할 수 있으면 표시한다.

## 이름 — 접두어 = 그 코드가 다루는 데이터의 소유자

한 테이블 묶음을 여러 소유자(예: 본 문서와 그 시뮬레이션본)가 행 단위로 나눠 쓰면:

1. 함수가 받는 키로 소유자가 정해지는가? — 행 ID 하나로 특정되면 **공용**(중립 이름), 소유자 전용 키를 받으면 그 소유자 이름.
2. 한 클래스·모듈에 두 갈래가 섞이면 **나눈다**. 이름 하나가 두 갈래를 덮으면 다음 사람이 오독한다.
3. 공용 규칙(계산·채번·저장값 규칙)은 한 곳에 모은다 — 경로마다 각자 구현하면 갈라진다.

- 🚫 소유자 A 이름의 코드가 소유자 B 의 키를 받는 것 — 그 함수는 공용이다.
- 🚫 화면 이름으로 서비스를 짓는 것 — 같은 로직을 여러 화면이 쓴다.
- 함수 이름은 동사로 시작한다(`get`·`find`·`build`·`compute`…). 판정 함수만 `is`·`has`.
- 배치 전용 쿼리는 화면용 쿼리와 폴더를 나누고 **잡 이름**을, 여러 잡 공용이면 주제 이름을 붙인다.

## 주석

| 대상 | 분량 |
|---|---|
| 클래스·모듈·타입 | 1~4줄 |
| 함수·필드 | 1~2줄 |
| 로직(블록·인라인) | 1줄 |

- 소스에는 "무엇을 하는지"와 코드만 봐서는 모르는 제약만. 코드를 되풀이하는 주석, "왜 이렇게 됐는지" 장문은 이슈·인계 문서로.
- 보안 수정의 주석·커밋 메시지에 공격 방법을 풀어 쓰지 않는다.
- 공개 API 에 문서 주석을 다는지, 어떤 형식인지는 언어·프로젝트 관례를 따른다(스택 팩이 구체화한다).
