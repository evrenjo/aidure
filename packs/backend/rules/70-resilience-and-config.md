회복 탄력성 라이브러리(재시도·서킷 브레이커·한도)와 HTTP 클라이언트 설정이 프로젝트에 이미 있으면 **그것을 쓴다.** 새로 들이거나 직접 구현하지 않는다.

## 1. 타임아웃

- **모든 원격 호출에 타임아웃** — 연결·응답 둘 다. 같은 장비의 다른 프로세스 호출도 마찬가지. 라이브러리 기본값이 "무한" 인 경우가 많다.
- 값은 하위 서비스의 지연 분포에서 정한다 — 허용할 오탐 비율(예: 0.1%)에 해당하는 백분위(p99.9) 근처. 너무 길면 자원을 붙잡고, 너무 짧으면 재시도가 몰린다.
- **시간 예산을 전파한다** — 상위 요청에 남은 시간 안에서 하위 타임아웃을 정한다. 상위가 이미 포기한 요청을 하위에서 계속 처리하지 않는다.

## 2. 재시도

- **재시도는 안전할 때만** — 읽기·멱등 작업, 또는 멱등 키를 함께 보내는 쓰기. 부작용이 있는 호출은 "실패=안 일어남" 이 아니다(타임아웃 뒤에도 처리됐을 수 있다).
- 4xx(요청 자체가 틀림)는 같은 요청으로 재시도하지 않는다. 408·429·503 은 재시도할 수 있고 `Retry-After` 를 존중한다.
- **지수 백오프 + 상한 + 지터 + 횟수 제한**. 지터 없이 백오프만 하면 실패한 호출이 같은 시각에 다시 몰린다.
- **한 층에서만** — 여러 층이 각자 재시도하면 호출 수가 곱으로 불어난다(층마다 3회 × 5층 = 243배). SDK·클라이언트·게이트웨이·큐가 이미 재시도하면 더하지 않는다.
- 과부하 때 재시도가 부하를 키우지 않게 **재시도 예산**(토큰 버킷 등)이나 서킷 브레이커를 기존 도구로 건다. 서킷 브레이커는 상태 전환을 로그·메트릭으로 남긴다.
- 재시도율을 볼 수 있게 한다 — 평소 드물던 재시도가 장애 때 처음 몰려서 문제를 키운다.

## 3. 대체 동작(폴백)

- 실패하면 다른 경로로 넘기는 폴백은 **평소에 안 도는 코드**라 장애 때 처음 실행되며 더 큰 문제를 만들기 쉽다. 기본은 폴백 없이 오류를 올려 **호출자가 재시도**하게 한다.
- 꼭 필요하면(캐시·기본값) 사람과 합의하고, 틀리거나 오래된 데이터가 조용히 나가지 않는지·그 경로가 테스트되는지 본다.
- **인가·결제·재고 판정은 실패 시 거부 쪽**(fail closed). 판정 서비스가 죽었다고 허용하지 않는다.

## 4. 과부하

- 처리할 수 없는 요청은 빨리 거절한다(429·503) — 받은 요청의 지연을 지키는 쪽이 모두 느려지는 것보다 낫다.
- 큐에 쌓인 작업은 **대기 시간 상한**을 두고 너무 오래된 것은 버리거나 격리한다.
- 목록·내보내기 API 는 페이지로 나눠 한 요청의 일을 제한한다.

## 5. 메시지·배경·스케줄 작업

- 소비자는 **같은 메시지를 두 번 받을 수 있다**고 가정한다(최소 한 번 전달). 처리 기록·유니크 키로 멱등하게.
- 작업은 **재진입 가능**하게 — 중간에 죽어도 다시 돌리면 같은 결과. 한 트랜잭션으로 묶거나 멱등하게 나눈다.
- 반복 실패하는 메시지는 무한 재시도하지 않는다 — 상한 뒤 격리(데드 레터) 등 기존 방식으로, 알림이 걸리게.
- 인스턴스가 여러 개면 같은 스케줄 작업이 **동시에 여러 번** 돈다. 한 번만 돌아야 하면 DB 잠금 등 공유 수단으로(인메모리 플래그는 인스턴스마다 따로다).
- 여러 인스턴스·클라이언트가 같은 시각(정각·자정)에 몰리지 않게 주기 작업에 지터를 둔다.
- 메시지 발행과 DB 변경을 함께 보장해야 하면 아웃박스 등 기존 방식을 찾는다 (「백엔드 계층·이름·주석」 트랜잭션 경계).

## 6. 설정

- 배포마다 다른 값(접속 정보·URL·자격·기능 플래그)은 **코드 밖**(환경 변수·마운트된 설정·비밀 저장소 — 프로젝트 방식)에서 읽는다. 코드가 "지금 운영인가" 로 분기하지 않는다 — 값 하나하나를 설정으로.
- 새 설정 키는 **안전한 기본값**과 함께 정의하고, 필수 값이 없으면 **기동 때** 명확한 메시지로 실패시킨다(요청 처리 중에 터지지 않게).
- 배포 매니페스트·CI 변수 주입이 따로 관리되는 프로젝트면 거기에 키를 넣는 일은 담당자에게 요청한다 — 앱 쪽 기본값만으로 기동되게 한다.
- 비밀값은 설정 기본값에 넣지 않는다 (「백엔드 보안」).

## 7. 인스턴스·기동·종료

- **상태 없는 프로세스** — 인스턴스는 늘고 줄고 재시작된다. 요청 사이에 공유돼야 하는 상태(세션·진행 상황·잠금·카운터)는 메모리·로컬 디스크가 아니라 DB·캐시에. 고정 세션(sticky)에 기대지 않는다.
- **빠른 기동** — 기동 때 무거운 작업을 하지 않는다. 연결 준비가 끝나기 전에는 트래픽을 받지 않게(준비 상태 체크).
- **정상 종료** — 종료 신호(SIGTERM)를 받으면 새 요청·새 작업을 받지 않고, 진행 중인 요청을 마치고, 끝내지 못한 작업은 큐로 돌려놓는다. 유예 시간(쿠버네티스 기본 30초) 안에 끝나게.
- **헬스 체크** — 살아 있음(재시작 판단)은 **외부 의존(DB·다른 서비스)을 보지 않는다** — 의존 장애 때 모든 인스턴스가 재시작돼 장애가 번진다. 의존 확인은 준비 상태(트래픽 판단)에만, 그것도 기존 관례대로.
