## 먼저 확인한다

프로젝트가 쓰는 화면 틀(스캐폴드·리스트·페이지 구성 요소)과 미리보기·스크린샷 테스트 설정을 먼저 찾아 맞춘다. 시스템 구성 요소는 원형 화면·회전 입력·글자 크기·상시 표시 처리를 이미 해 주는 경우가 많으니 직접 그리기 전에 그것부터 쓴다.

## 짧은 상호작용

- 한 화면에 핵심 정보와 한두 동작. 사용자가 **몇 초 안에** 끝낼 수 있어야 한다(손목을 든 채 오래 쓰게 하지 않는다).
- 화면 계층은 얕게. 내비게이션은 세로 방향(리스트·세로 페이지)으로 두어 크라운·회전 입력으로 오갈 수 있게 한다.
- 느린 연결·오프라인을 전제로 한다 — 운동·이동 중에 쓴다. 로딩 중에도 마지막으로 받은 값을 보여 준다.

## 화면 크기·원형 화면

- **기본은 스크롤 가능한 배치** — 화면 크기·글자 크기 설정과 상관없이 모든 요소에 닿을 수 있다. 대화 상자도 스크롤되게.
- 여백은 고정 픽셀보다 **화면 비율 기준**으로. 원형 화면 가장자리에서 글자·컨트롤이 잘리거나 겹치지 않게 한다.
- 큰 화면에서만 더 보여 주는 것은 화면 너비 기준점으로 나눈다. 작은 화면이 기본이다.

## 글자·터치 영역

- **사용자 글자 크기 설정을 따른다** — 키워도 잘리거나 겹치지 않아야 한다. 넘치면 말줄임, 자동 크기 조절은 최소·최대를 정한다.
- 터치 영역은 플랫폼 기준 이상(Wear OS 품질 기준 최소 48×48dp). 중요한 동작은 화면 너비 버튼으로, 컨트롤 사이 간격을 둔다.
- 글자 크기 최소값은 플랫폼 품질 기준을 따른다(Wear OS 핵심 글자 12sp·보조 글자 10sp 이상).

## 크라운·회전 입력

- 스크롤 가능한 화면은 **회전 입력으로도 스크롤**돼야 한다. 시스템 리스트 구성 요소를 쓰면 대개 자동이다 — 직접 만든 스크롤은 포커스를 받게 해야 회전 이벤트가 온다.
- 회전에는 **눈에 보이는 반응**(스크롤 표시, 값 변화)을 준다. 반응이 없으면 사용자는 동작하지 않는다고 본다.
- 회전 동작에는 같은 일을 하는 터치 동작도 둔다. watchOS 는 크라운 누르기를 앱에 주지 않는다(시스템 전용).

## 상시 표시(Always On · ambient)

- **민감 정보를 가린다** — 건강·금융 정보는 상시 표시 상태에서 흐리게·숨김 처리한다(플랫폼의 개인정보 가림 수단을 쓴다).
- 갱신은 드물다(대개 1분 단위). 초 단위 값·애니메이션은 멈추고 정적 값이나 `--` 같은 자리 표시로 바꾼다. 움직임은 뚝 끊지 말고 정지 상태로 넘긴다.
- 대부분 검게, 밝은 넓은 면을 줄이고 부가 정보는 어둡게. 번인 보호 기기는 화면이 조금씩 이동하므로 가장자리에 중요한 요소를 붙이지 않는다.
- 상태가 바뀔 때 배치를 크게 바꾸지 않는다 — 조작할 수 없는 컨트롤은 지우지 말고 비활성 모양으로.
- 화면을 계속 켜 두는 설정은 드문 경우에만 쓴다(배터리를 크게 쓴다).

## 접근성

- 스크린 리더(VoiceOver·TalkBack)용 이름을 모든 컨트롤·아이콘·컴플리케이션·타일에 단다. 중복된 단어 없이 짧게.
- 회전 입력 지원 자체가 접근성이다 — 작은 화면에서 정확히 누르기 어려운 사용자와 스크린 리더 사용자가 쓴다.
- 색만으로 상태를 구분하지 않는다.

## 확인

- **원형 작은 화면과 큰 화면**, 사각 화면을 지원하면 사각도, 가장 큰 글자 크기로 미리보기·스크린샷을 본다.
- 상시 표시 상태를 시뮬레이터·에뮬레이터나 기기에서 켜 본다(미리보기는 시스템 흐림을 재현하지 않는 경우가 있다).
- 스크린 리더를 켜고 주요 흐름을 한 번 돈다. 못 본 조합은 미확인으로 보고한다.
