## 독립 실행이 기본

- 사용자는 **폰 앱 없이, 폰이 멀리 있을 때도** 워치 앱을 쓴다. 폰 앱이 있어도 워치 앱이 먼저 설치될 수 있다.
- 폰 앱이 필요한 기능에서 폰 앱이 없음을 감지하면 설치를 안내한다(플랫폼의 기기 능력 조회 API 로 확인).
- 독립 실행 선언(Wear OS 매니페스트의 standalone 값, watchOS 의 "iOS 앱 없이 실행" 설정)은 **실제 동작과 맞춘다** — Wear OS 는 스토어가 이 값을 검증하고, 잘못 선언하면 폰과 짝지어지지 않은 기기에서 앱이 보이지 않는다.
- 독립 실행이면 계정 생성·로그인, 필요한 권한 요청, 데이터 받기, 푸시 수신이 **워치 안에서** 끝나야 한다.

## 데이터 동기화 — 경로를 고른다

| 목적 | 쓰는 경로 |
|---|---|
| 저장·조회·여러 기기 상태 맞추기(기록·설정·프로필) | **서버·클라우드 직접** — 워치가 직접 네트워크로 |
| 폰이 가까이 있을 때 빠른 전달, 원격 조작, "폰에서 열기", 초기 설정 토큰 전달 | 폰·워치 연동 API(WatchConnectivity · Wearable Data Layer 류) |

- 폰 연동 API 는 **기회가 될 때 쓰는 보조 경로**다. 유일한 데이터 공급원으로 두지 않는다 — 연결이 없을 때도 앱이 쓸모 있어야 한다.
- 보내기 전에 세션 활성·상대 앱 설치·도달 가능 여부를 확인한다. 즉시 메시지는 상대가 도달 가능할 때만 성공한다.
- 전송 방식의 의미를 구분한다 — "최신 상태 덮어쓰기", "순서대로 반드시 전달", "즉시 메시지", "파일"은 서로 다르다. 기존 코드가 쓰는 방식을 바꾸면 유실·중복을 확인한다.
- **빠른 연속 갱신 대신 상태 변화만** 보낸다 — 전송마다 기기가 깨어난다. 리스너는 필요할 때만 등록한다.
- Wear OS 데이터 레이어는 폰·워치 앱의 **패키지 이름과 서명이 같아야** 통한다. watchOS 도 워치 앱 번들 ID 가 폰 앱 번들 ID 에 기반해야 한다 — 식별자·서명 설정을 바꾸지 않는다.
- 여러 워치를 한 폰에 짝지을 수 있다(watchOS) — 세션 비활성·재활성 처리를 빼지 않는다.
- 네트워크 경로(폰 경유·Wi-Fi·셀룰러)가 바뀌어도 동작하는지 본다.

## 워치에서의 로그인

- 워치에서 비밀번호를 치게 하는 것은 마지막 수단이다. 플랫폼 자격 증명 API(패스키·저장된 비밀번호·연동 로그인), 폰에서 승인하는 방식(OAuth PKCE·기기 승인), 폰 앱의 토큰 전달을 먼저 쓴다.
- 폰 토큰 전달은 폰 앱이 없거나 다른 OS 폰과 짝지어진 경우를 위한 **대체 방법을 함께** 둔다.
- 로그인 없이 쓸 수 있는 기능은 로그인 없이 열어 둔다.

## 건강·센서 데이터

- **필요한 데이터 종류만** 요청한다 — 사용자는 종류별로 허용·거부한다. 요청 목적 설명 문구가 없으면 요청 자체가 실패하는 플랫폼이 있다.
- **거부돼도 동작한다** — watchOS 는 읽기 거부를 앱에 알리지 않고 "데이터 없음"으로 보인다. 빈 데이터를 오류로 다루지 않는다.
- 기기가 잠기면 건강 데이터 저장소를 읽지 못할 수 있다(백그라운드 읽기 실패를 처리한다).
- Wear OS 권한은 버전마다 바뀐다 — 최신 대상 버전에서는 `BODY_SENSORS` 류 대신 세분된 건강 권한(`android.permission.health.*`), 백그라운드는 별도 권한. 프로젝트의 대상 버전을 보고 맞춘다.
- 건강 데이터를 **광고에 쓰지 않고, 동의 없이 제3자에 넘기지 않고, 팔지 않는다.** 로그·크래시 보고·분석 이벤트에 싣지 않는다. 개인정보 처리방침이 필요하다.
- 화면·알림·컴플리케이션에서 남이 볼 수 있는 상태면 가린다(20 룰 상시 표시 참고).

## 확인

- 폰 앱 없음 · 폰 연결 끊김 · 폰 연결됨 세 경우를 한 번씩 돌린다. 연동은 **실기기 한 쌍**으로 확인하는 게 원칙이다.
- 권한 거부 상태로 주요 화면을 한 번 연다. 못 본 경우는 미확인으로 보고한다.
