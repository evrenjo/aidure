# tidy: 남은 파일 정리

지우는 일은 되돌리기 어렵다. **찾기 → 표로 보이기 → 승인 → 지우기 → 검증** 순서로 하고, 승인 없이 지우지 않는다.

## 1. 범위 정하기

| 범위 | 언제 | 명령 |
|---|---|---|
| 이번 작업 (기본) | 방향을 바꾼 직후 · 단계를 끝낼 때 | `node packs/core/bin/tidy.js --new` |
| repo 전체 | 사용자가 "전체 정리" 를 말했을 때 | `node packs/core/bin/tidy.js [--repo <이름>]` |

## 2. 후보 모으기

- **도구 결과**: 이번 작업 새 파일 · 안 쓰는 자료 · 링크 없는 문서 · 백업 이름. 도구는 이름이 글에 나오는지만 본다. 후보는 추정이므로 하나씩 근거를 확인한다 (설정 · 빌드 스크립트 · 동적 경로 · 외부 링크로 쓰일 수 있다).
- **대화에서 바뀐 방향**: 이번 대화에서 버린 방식(예: A 화면 구조 → B 로 바꿈)으로 만든 파일을 직접 꼽는다. 도구의 「이번 작업 새 파일」 목록과 맞춰 본다.
- **코드**: 도구가 알려 준 프로젝트 도구(knip · vulture · detekt 등)가 있으면 돌린다. 없으면 지우려는 함수 · 파일을 이름으로 전수 검색해 호출부가 0 인지 확인한다.
- 원래 있던 파일(이번 작업 전부터 있던 것)은 근거가 분명할 때만 후보로 넣고, 「원래 있던 것」 이라고 표시한다.

## 3. 표로 보이고 묻기

| 파일 | 왜 남았나 | 근거 | 제안 |
|---|---|---|---|
| `repos/app/src/old-list.tsx` | B 구조로 바꾸며 안 쓰게 됨 | import 0건 (`grep -rn old-list`) | 지움 |
| `repos/plan/30-screens/shots/v1-main.png` | 화면 1차안 | 어느 문서에도 없음 | 지움 |
| `repos/app/docs/setup-old.md` | 원래 있던 것 | 링크 0건, 내용이 README 와 같음 | 사용자 확인 |

- 선택지 질문으로 묻는다: 표대로 지움(권장) · 일부만 · 그대로 둠.
- 기획 repo · 이슈 repo 의 문서는 상태(동결 · 대체됨)로 남기는 관례가 있으면 지우지 않고 그 관례를 따른다. 결정 기록은 지우지 않는다.
- 레거시(AS-IS) repo 와 남이 만든 변경(작업 트리에 원래 있던 수정)은 건드리지 않는다.

## 4. 지우기

- 추적되는 파일은 `git rm`, 커밋 안 한 새 파일은 지운다. 휴지통 폴더(`old/` · `backup/`)로 옮기지 않는다 (이력은 git 에 있다).
- 지운 파일을 가리키던 곳(import · 링크 · 메뉴 · 설정 · 문서의 경로)도 같은 변경에서 고친다.
- 커밋은 사용자가 요청할 때. 메시지는 `chore: 안 쓰는 파일 정리 (<요약>)`.

## 5. 검증 · 보고

```bash
node packs/core/bin/check-refs.js             # 지운 파일을 가리키는 죽은 참조
node packs/core/bin/tidy.js --count --new     # 남은 후보 (repo 전체를 정리했으면 --new 없이)
```

빌드 · 테스트(그 repo 의 명령)와 기획 repo 면 `kedovi docs build` 도 돌린다. 보고: 지운 것 · 남긴 것(이유) · 검증 결과.
