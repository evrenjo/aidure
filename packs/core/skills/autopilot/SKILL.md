# autopilot — 자율완주 모드

사용자가 자리를 비우거나 "알아서 끝까지" 를 원할 때 쓴다.

> 멈추는 대신 적는다 · 추측 대신 표시한다 · 자동 채택할 수 있으면 채택하고 끝까지 구현한다 · 파괴적이면 손대지 않고 표시만 한다 · 다 하면 검증 → 핸드오프 → 커밋 (푸시 없음).

범위 = 호출할 때 덧붙인 설명, 없으면 직전 대화의 작업. **범위를 임의로 넓히지 않는다** — 인접 개선 아이디어는 이슈 목록의 논의 포인트로만.

## 원칙

1. **대기 금지** — 이 모드에서는 질문하고 기다리지 않는다. 결정이 필요하면 이슈 목록에 적고 다음으로 넘어간다. (이 모드 호출 자체가 "무응답이면 표시하고 넘어가라" 는 사용자 지시다.)
2. **할 수 있는 건 다 구현** — 기존 코드·정본·문서에서 답이 나오는 선택은 자동 채택한다. 빈 구현(stub·no-op)·"다음에"·TODO 마커로 미루지 않는다.
3. **이슈 목록에 올리는 것만**
   - 양쪽 다 합리적인 진짜 trade-off (정본으로 안 풀림)
   - 외부(다른 팀·운영·고객) 답에 의존
   - 근거가 없어 추정이 들어가야 하는 지점
   - 파괴적·되돌리기 어려운 조치 (배포, 운영 데이터 변경, 대량 삭제, 외부 발신, 강제 푸시)
4. **이슈 목록** — `handoffs/{id}/AUTOPILOT-ISSUES.md` 에 누적한다.

   ```markdown
   # 자율완주 이슈 — 논의용 (YYYY-MM-DD)

   | # | 항목 | 종류 | 임시 결정 (진행하려고 택한 값) | 사용자가 정할 것 |
   |---|---|---|---|---|
   | 1 | … | trade-off / 외부답변 / 근거없음 / 파괴적 | … 또는 `- (미착수)` | … |
   ```

   파괴적 항목은 임시 결정 없이 **미착수**로 둔다.
5. **완주 = 더 구현할 것이 없고 이슈 목록만 남은 상태**
   1. 검증 — 해당 repo 의 빌드·린트·타입체크·테스트, 필요하면 쿼리. 걸리는 것 0건 + 검증표.
   2. 핸드오프 — handoff 스킬을 따른다. 같은 날 이미 핸드오프가 있으면 덮어쓰지 말고 오늘 섹션에 "자율완주" 소섹션을 **추가**한다.
   3. 커밋 — 이 모드 호출이 **커밋 승인**이다. repo 마다 그 폴더에서, 프로젝트 커밋 규칙대로. **푸시는 하지 않는다.**

## 금지

- 파괴적 조치 자동 실행 (위 3번 마지막 줄 전부)
- 푸시 — 커밋까지만
- 추측으로 채워 구현 — 모르는 건 "근거없음" 으로 표시
- 다른 사람 담당 영역 수정

## 완주 보고

- 구현 완료 항목 (repo · 커밋 SHA — 미푸시이므로 "진행 중" 상태임을 명시)
- 이슈 목록 경로 + 항목 수
- 검증표
- 핸드오프 처리 방식 (추가 / 새로 작성)
- 푸시 안 함
