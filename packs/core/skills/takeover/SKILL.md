# takeover — 인수인계

다른 개발자(`<from>`)의 핸드오프를 읽고, 사용자가 고른 미완 작업은 **내 작업별 기록**으로, 고른 TODO 항목은 **내** `TODO.md` 로 옮겨 이어받는다.
`<from>` 의 폴더(`handoffs/<from>/`)는 **읽기만** 한다 — 고치지 않는다.

## 0. 대상 정하기

- 인자로 `<from>` 이 없으면 팀 현황을 보여 주고 누구 작업을 인수할지 묻는다: `node packs/core/bin/team-status.js`
- `<from>` 이 본인이면 "본인 작업은 resume 으로 재개합니다" 알리고 멈춘다.

## 1. 읽기 — 원격 기준

```bash
node packs/core/bin/team-status.js --id <from>     # git fetch 후 원격의 LATEST · 미완 작업 · TODO(번호 · 인수 여부)
```

보고:

```
인수인계 — <from> → {나}
📌 마지막 핸드오프 (YYYY-MM-DD, N일 전): 핵심 · 진행 중
🌿 작업 브랜치: {repo: 브랜치 (push 됨 | 이 PC 에만 있음)}
🧩 미완 작업: {작업 이름 (남은 [ ] 수)} …
📋 TODO: 1. … 2. … (이미 인수된 것은 "인수됨 → 누구")
```

- 작업 브랜치가 **"이 PC 에만 있음"** 이면 코드를 받을 수 없다고 분명히 알린다 — `<from>` 에게 push 를 부탁해야 한다.
- 아직 push 되지 않은 `<from>` 의 핸드오프는 보이지 않는다. 기록이 오래됐으면(3일 넘게) 그 사실도 알린다.
- 인수할 작업의 자세한 내용은 `<from>` 의 작업별 기록(`handoffs/<from>/topics/<작업>.md`, 원격이면 `git show @{u}:<경로>`)에서 머리 · `## 요약` · 마지막 날짜 섹션을 읽는다. 특정 내용은 `node packs/core/bin/handoff.js find <작업> --id <from>`.

## 2. 묻기

"어떤 미완 작업 · TODO 항목을 인수할까요? (이름 · 번호 · 전부 · 안 함)" — 답 없이 옮기지 않는다. 코드가 없는 항목은 그 사정을 함께 적어 권한다.

## 3. 옮기기

```bash
node packs/core/bin/team-status.js --take <from> --items <번호,…|all>
```

- 고른 **TODO 항목**만 위 명령으로 옮긴다: 내 `handoffs/{나}/TODO.md` 에 `- 항목 ← <from> 에게서 인수 (날짜)` 로 붙는다. 이미 인수된 항목은 건너뛴다.
- 고른 **미완 작업**은 TODO 로 옮기지 않는다. 내 작업별 기록(`topics/<같은 이름>.md`)을 만들어 `상태: 진행 중`, `관련:` 에 `<from> 에게서 인수` 와 원래 기록 경로, `## 완료 조건` 에 남은 `[ ]` 항목을 옮겨 적는다.
- 팀 현황은 이 표시를 보고 `<from>` 의 항목을 "인수됨" 으로 센다 (`<from>` 폴더는 그대로).

## 4. 코드 이어받기

인수한 항목의 작업 브랜치가 push 돼 있으면, 그 repo 에서 `git fetch` 후 그 브랜치로 옮겨 이어서 할지 묻는다. 옮기기 전 미커밋 변경이 있으면 먼저 알린다.

## 5. 마무리

- 인수 기록(내 TODO.md · 작업별 기록)은 다음 handoff 가 commit · push 한다. 바로 공유하려면 사용자에게 지금 handoff 할지 묻는다.
- 이어서 할 첫 작업 1~2건을 제안한다.

> 터미널에서는 `aikit team <from>` (보기) · `aikit team <from> --take <번호,…|all>` (옮기기) 로 같은 일을 한다.
