## 변경 영향 전수 점검 체크리스트

"수정한 파일" 이 아니라 **"바꾼 계약"** 기준으로 영향 범위를 잡아, 읽기만 바꾸고 쓰기를 빠뜨리는 반쪽 적용을 막는다.
규모가 작아 보여도 아래 중 하나라도 해당하면 통째로 수행한다.

- 조회의 **기준 테이블**이나 **조인 키**를 바꿨다
- 테이블·컬럼·응답 필드의 **의미**를 바꿨다 (기본값·단위·NULL 처리·판정 기준 포함)
- 어떤 값을 **정본으로 삼는 위치**를 옮겼다 (본문 ↔ 링크 테이블, 엔티티 ↔ 정책, 화면 ↔ 서버)
- 정합을 맞추려 한쪽(배치 / 온라인 / 화면)만 손봤다

### ① 계약 식별 — 바꾼 것을 한 줄로

```
(X) OrderQuery.java 수정
(O) 주문 목록의 기준 테이블: order → order_membership (조인 키 owner_code)
```

테이블이면 테이블명, 컬럼이면 컬럼명, 응답이면 필드명을 적는다. 이 한 줄이 ②의 검색 대상이다.

### ② 쓰기·읽기 경로 전수 검색 — 한 줄씩 판정

①의 대상에 접근하는 **모든 지점**을 검색해 새 계약 충족 여부를 표로 만든다. 저장소 클래스·쿼리 타입·원시 SQL 문자열까지 여러 표기로 검색하고, 생성된 클라이언트·설정·문서·다른 repo 도 소비처로 본다. **"해당 없음" 도 기록**한다 (안 본 것과 구분).

| 경로 | 새 계약 충족 | 비고 |
|---|---|---|
| `OrderService.create` | O | |
| `OrderCopyService.copy` | **X** | ← 이런 칸이 결함이다 |

### ③ CRUD 4면 대칭 — 한 칸이라도 비면 미완료

본문과 짝을 이루는 데이터(멤버십·링크·스냅샷)는 생성·복사·삭제·머지(클론) 4면을 표로 채운다.
읽기를 A 로 옮겼으면 **A 에 쓰는 4면이 전부** 있어야 한다. 대칭 도메인이 있으면 양쪽 다 채운다.
복사·클론 기능은 컬럼보다 먼저 **INSERT 하는 테이블 집합**을 원본 동작과 맞춘다 — 아예 안 만드는 테이블은 컬럼 대조로는 보이지 않는다.

### ④ 데이터 짝 검증 쿼리 — 리뷰가 아니라 DB 로 증명

"0 이어야 정상" 인 쿼리를 만들어 실행하고 결과를 이슈 문서·핸드오프에 남긴다. 재발 감지용으로 파일에 보존한다.

```sql
-- 본문은 있는데 짝이 없음 = 0
SELECT count(*) FROM parent p WHERE p.is_deleted = false
  AND NOT EXISTS (SELECT 1 FROM link l WHERE l.parent_id = p.id AND l.is_deleted = false);
-- 자연키 중복 = 0 (배수 조인 조기 감지)
SELECT count(*) FROM (SELECT k1, k2 FROM link WHERE is_deleted = false GROUP BY 1, 2 HAVING count(*) > 1) x;
```

중복 키 검사를 꼭 넣는다 — 배수 조인은 화면에서 "행이 늘었다" 로만 보여 원인 추적이 오래 걸린다.

### 폼을 쓰는 CRUD — 입력 가능한 모든 컨트롤에 입력·미입력·초과

| 케이스 | 보는 것 |
|---|---|
| 입력 | 유효한 값 저장 → 화면·DB 에 그대로 남는가 |
| 미입력 | 필수면 그 필드를 가리키는 안내 + 저장 차단 / 선택이면 기본값이 규칙대로 |
| 초과 | 컬럼 길이·정밀도 초과 → **400 + 필드 안내**여야 한다. **500 이면 결함** |

- 필수 여부·길이는 화면 표시(`*`, maxLength)가 아니라 서버 검증과 DB 제약에서 먼저 확정한다. 화면만 막으면 API 계약은 안 지켜진 것이다.
- 컨트롤 종류마다 "미입력" 모양이 다르다 (빈 문자열·미선택·해제·빈칸). 0 과 빈칸을 한 케이스로 묶지 않는다.
- 검증표에 컨트롤 한 줄씩: `컨트롤 / 타입 / 필수 / 입력 / 미입력 / 초과 / 판정`. 읽기 전용은 제외 사유를 적는다.

### 테스트 케이스는 diff 에서 뽑지 않는다

- ②의 표에 오른 **모든 경로를 1회씩** 실행한다. 최소 = 그 화면·기능의 CRUD 전부.
- 같은 커밋이 양쪽을 만든 경로는 반드시 통과한다 — 그것만으로 검증하지 않는다.
- 비동기 화면은 응답이 끝난 뒤에 판정한다 (로딩 중 캡처로 "0건" 오판 금지).
- **fix 커밋도 feature 와 같은 검증표**를 만든다. 검증표 없는 변경은 완료로 보고하지 않는다.

### 값을 고를 때 정본 순서를 먼저 찾는다

"최신 / 가장 큰 것" 을 고를 때 문자열 max·사전순을 그대로 쓰지 않는다. 업무 순서가 있는 코드값은 그 순서가 상수로 이미 정의돼 있는지 먼저 검색한다.

### 백필·정리 SQL

- **멱등**(`NOT EXISTS` 가드) + **중복 방어**(`DISTINCT ON` 등). 대상에 중복이 있으면 백필이 그 중복을 배수로 키운다.
- 실행 전 트랜잭션 안에서 dry-run(BEGIN/ROLLBACK)으로 건수를 확인하고, 실행 후 ④ 검증 쿼리를 돌린다.
- 파괴적 DELETE 는 대상·보존 기준을 SQL 주석에 적고 사용자 승인을 받는다.
