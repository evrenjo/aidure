## 근거와 검증

- **확인됨 / 추정 / 미확인을 드러낸다** — 확인됨은 근거(`파일:라인`·실행한 명령과 결과)와 함께, 부족하면 "~로 보입니다, 확인 필요", 안 봤으면 "미확인 — 안 봤음".
- **지어내지 않는다** — API·옵션·경로·명령·설정 키는 코드·문서·`--help` 로 실존을 확인하고 쓴다.
- **한 갈래로 일반화하지 않는다** — 경로가 여럿이면 경로마다 판정한다.
- **기획 문서는 ID 단위로 읽는다** — 정의는 `node packs/core/bin/docs-site.js show <ID>`, 쓰는 곳은 `… refs <ID>`. 큰 문서를 통째로 열지 않는다. 「상태: 동결」 문서는 고치지 않는다. 기획 문서를 쓰거나 고칠 때는 `.agents/rules/core--45-docs-writing.md` 를 읽는다.
- **구현한 기획 ID 는 코드에 `@spec` 주석으로 한 번**: 진입점 머리 주석에 (`// @spec SCR-ORD-01 FN-ORD-003`, 테스트는 수용 기준 ID). 커밋 전 `aidure docs trace --new` (Claude Code 는 커밋 때 훅이 알린다). 자리 · 꼴은 「기획 문서 쓰기」 룰.
- **기획 문서는 낡았을 수 있다: 코드 · 화면으로 다시 확인하고, 다르면 판정한다** (정본이 맞음 · 구현이 맞음 · 판단 불가). 문서 고치기는 `vars.docs.syncMode` (지금 `{{ws:vars.docs.syncMode}}`) 대로, 절차는 「기획 문서 쓰기」 룰.
- **흔한 방식 · 업계 관례는 검색해서 말한다** — "보통은 ~" 을 말하거나 사용자가 "아닌가? · 보통 ~던데" 라고 물으면 `common-practice` 스킬로 출처를 확인한다. 검색할 수 없으면 "검색 불가: 내 지식 기준" 이라고 밝힌다.
- **닫는 주장은 더 강한 근거로** — "없다·안 된다" 도 주장이다. 검색 0건은 "못 찾았다" 이고, 범위·인코딩·제외 경로를 확인한 뒤에만 "없다".
- **완료는 실행한 검증으로 말한다** — 해당하는 테스트·린트·타입체크·빌드를 돌려 결과를 보이고 못 돌린 것은 "미실행" 으로 적는다. 오류를 끄거나 테스트를 건너뛰어 통과시키지 않는다.
- **검증 결과는 표로** (`대상 / 케이스 / 방법 / 기대 / 실제 / 판정`) — 검증을 계획하거나 완료를 보고하기 전에 `.agents/rules/core--21-verification.md` 를 읽는다.
- **기존 동작·계약을 바꾸면** 시작 전에 `.agents/rules/core--30-change-impact.md` 를 통째로 수행한다.
