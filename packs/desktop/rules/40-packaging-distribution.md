## 공통

- **배포 빌드는 서명한다** — 서명하지 않은 앱은 Windows·macOS 가 실행을 막거나 강한 경고를 띄운다.
- **서명 자료는 저장소 밖에** — 인증서·키·암호·공증 계정은 CI 비밀·하드웨어 키·클라우드 서명 서비스로. 스크립트에 값을 적지 않고 로그에 찍히지 않게 한다.
- **서명 단계를 끄거나 "실패 무시"로 바꾸지 않는다** — 로컬 개발 빌드만 예외로 두는 기존 구분을 따른다.
- **권한 선언은 필요한 것만** 더하고, 더한 이유를 변경 설명에 적는다.

## OS 별

| OS | 확인할 것 |
|---|---|
| macOS | 배포용 개발자 인증서로 서명 + **하드닝된 런타임** 켬 + **보안 타임스탬프** 포함 → **공증** 제출 → 티켓 **스테이플**. 앱뿐 아니라 디스크 이미지·설치 패키지도 공증 대상. 디버그용 entitlement 를 배포 빌드에 남기지 않는다 |
| Windows | 실행 파일·설치 프로그램·DLL 을 코드 서명하고 **타임스탬프**를 붙인다(인증서 만료 뒤에도 서명이 유효하도록). 패키지 형식(MSIX 등)이 서명을 요구하면 설치 자체가 안 된다. 평판 기반 경고(SmartScreen)는 서명 주체의 이력에 묶이므로 서명 주체를 함부로 바꾸지 않는다 |
| Linux | 배포 채널의 방식을 따른다 — 패키지 저장소 서명(GPG), 샌드박스 형식(Flatpak·Snap 류)은 **샌드박스 권한을 최소로**(홈 전체·호스트 파일 시스템 접근 대신 포털·파일 선택기). 권한은 정적이라 실행 중 넓힐 수 없다 |

## 자동 업데이트

- **업데이트 메타데이터와 파일은 HTTPS 로, 설치 전에 서명을 검증한다** — 검증을 끄는 옵션을 쓰지 않는다. 일부 셸은 검증을 끌 수 없게 되어 있고, macOS 의 일부 업데이트 방식은 앱이 서명돼 있어야만 동작한다.
- **업데이트 검사는 패키징된 앱에서만** — 개발 실행에서 업데이트를 받아 덮어쓰지 않게 한다.
- 업데이트 서명 키를 교체할 때는 이미 설치된 버전이 새 키를 받아들이는 경로를 먼저 배포한다. 한 번에 바꾸면 기존 사용자가 업데이트를 못 받는다. 개인 키를 잃으면 업데이트 경로가 끊기므로 보관·백업 방식을 확인한다.
- **버전 번호는 단조 증가** — 업데이트 판정이 버전 비교에 기대므로 되돌리거나 형식을 바꾸지 않는다.
- 다운그레이드 방지, 중단된 다운로드·설치, 설치 중 앱 실행 상태에서 깨지지 않는지 본다.

## 설치·제거·경로

- **설치 폴더는 읽기 전용으로 본다** — 사용자 데이터·설정·로그는 OS 가 정한 사용자 위치(Windows 알려진 폴더 API, macOS `Application Support`·`Caches`, Linux XDG 기준 디렉터리)에.
- 제거 시 무엇을 남기는지(사용자 데이터) 정해진 정책을 따른다. 관리자 권한은 설치에 꼭 필요할 때만 요구한다.
- **번들 식별자(앱 ID)는 바꾸지 않는다** — 바꾸면 OS 가 다른 앱으로 보아 설정·권한·키 저장소 항목·업데이트 경로가 끊긴다.

## 확인

- 패키징 변경은 **대상 OS 마다 설치 → 실행 → 업데이트 → 제거** 를 한 번씩 돌린다. 못 돌린 OS 는 미확인으로 보고한다.
- 서명 확인은 OS 도구로 한다(예: macOS 서명·공증 검사 도구, Windows 서명 검증 도구). "빌드가 성공했다"는 서명 확인이 아니다.
