## 먼저 볼 것

그 프로젝트가 포커스를 어떻게 관리하는지 읽는다 — 플랫폼 포커스 엔진(UIKit·SwiftUI focus, Android View·Compose focus)을 쓰는지, 웹 앱이면 공간 내비게이션 라이브러리나 자체 포커스 매니저가 있는지. **있는 방식에 맞춘다.** 한 화면에 두 방식을 섞지 않는다.

## 포커스

- **보이는 모든 조작 요소에 방향키로 닿는다.** 광고·팝업·플레이어 컨트롤·오류 화면도 포함.
- **포커스는 한 번에 하나, 눈에 띄게.** 크기·색·테두리·그림자 등으로 구분하고, 앱 안에서 같은 모양을 유지한다. 플랫폼 기본 포커스 효과가 있으면 그것을 쓴다(tvOS 는 시스템 효과 우선).
- **화면이 뜨면 바로 누를 수 있는 요소에 포커스를 둔다.** 웹 앱은 첫 요소에 초기 포커스를 명시한다.
- **사용자 입력 없이 포커스를 옮기지 않는다.** 예외: 포커스된 요소가 사라졌을 때 가장 가까운 요소로.
- **이동 순서는 기본 규칙을 먼저 믿는다.** 명시 지정(`nextFocus*` 류, 포커스 가이드)은 기본 순서가 어색할 때만. 요소는 격자로 정렬하고 대각선 배치를 피한다.
- 포커스되면 커지는 요소는 확대된 크기의 이미지와 주변 여백을 둔다(겹쳐 가리지 않게).
- 방향키를 빠르게 연타해도 요소가 겹치거나 깜박이지 않아야 한다.

## 키

| 키 | 기대 동작 |
|---|---|
| 방향키 | 포커스 이동(누른 방향과 같은 쪽). 전체 화면 콘텐츠에서는 콘텐츠 조작 |
| 확인(Select·Enter) | 포커스된 요소 실행. 재생 중이면 재생·일시정지 전환 |
| 재생·일시정지 | 재생 중 토글 |
| 뒤로 | 아래 표 |
| 메뉴 키 | **의존하지 않는다** — 없는 리모컨이 있다 |

뒤로 키는 **상세 → 이전(부모) 화면** 이 공통이고, 첫 화면에서의 동작은 플랫폼 정책을 따른다.

| 플랫폼 | 첫 화면에서 뒤로 |
|---|---|
| Android TV | 홈으로 나간다. 종료 확인 대화상자·무한 루프·화면 위 가짜 뒤로 버튼을 두지 않는다 |
| tvOS | 부모(최상위면 홈 화면)로. 게임 플레이 중만 일시정지 메뉴 |
| Samsung Tizen | 앱이 종료하거나 숨긴다(종료 가이드는 앱이 만든 종료 확인 팝업을 둔다 — 최신 점검표 확인). 길게 누름·Exit 키는 처리기를 두지 않는다 — Exit 는 팝업 없이 어디서든 즉시 종료되어야 한다 |
| LG webOS | 기본은 `history` 스택(`popstate`). 직접 처리하면 `disableBackHistoryAPI` + 키코드 461, 첫 화면에서 플랫폼 뒤로 동작(버전에 따라 종료 확인 또는 홈) |

웹 앱은 기본으로 오는 키(방향·확인·뒤로) 외의 키(재생·색상 키 등)를 플랫폼 API 로 **등록해야** 받는 경우가 있다(Tizen `tvinputdevice`).

## 포인터 리모컨

포인터 리모컨(webOS 매직 리모컨 류)이 있는 플랫폼도 **방향키 모드를 반드시 지원한다.** 방향키를 누르면 포인터 모드에서 방향키 모드로 바뀌므로, 마우스 hover 로 옮긴 포커스와 방향키 포커스가 어긋나지 않게 한 곳에서 관리한다. hover 전용 기능을 만들지 않는다.

## 10피트 화면

| 항목 | 기준 |
|---|---|
| 안전 영역 | Android TV: 가장자리 약 5%(960×540dp 기준 좌우 48dp·상하 27dp) · tvOS: 상하 60pt·좌우 80pt |
| 글자 | tvOS 기본 29pt·최소 23pt · webOS 권장 최소 20px(1920×1080 기준) |
| 조작 요소 | tvOS 기본 66×66pt·최소 56×56pt · webOS 권장 최소 75×75px(1920×1080 기준) |
| 대비 | 본문 4.5:1, 큰 글자·굵은 글자 3:1 (WCAG AA) |

- 가장자리에서 잘리는 글자·기능이 없어야 한다. 배경은 불투명, 가로 화면 전체를 채운다.
- 목록이 한 화면을 넘으면 스크롤 표시를 둔다. 오래 걸리는 작업은 진행 표시를 둔다.
- 시스템 글자 크기 설정이 커져도 잘리지 않게 고정 높이를 피한다.

## 텍스트 입력·로그인

- **입력은 최소로.** 로그인은 다른 기기(휴대폰·웹)나 플랫폼 계정 연동을 먼저 검토하고, 긴 입력은 다른 기기로 넘긴다.
- 입력란에는 종류(이메일·비밀번호·숫자)를 지정해 맞는 가상 키보드가 뜨게 한다.
- 길이 초과·특수 문자 입력에서 멈추거나 입력란 밖으로 넘치지 않아야 한다.
- 검색은 가능하면 플랫폼 음성 입력을 받는다.

## 화면 낭독기

| 플랫폼 | 낭독기 | 앱이 할 일 |
|---|---|---|
| Android TV | TalkBack | 모든 핵심 요소에 의미 있는 이름(`contentDescription` 등). "unlabeled" 가 들리면 실패 |
| tvOS | VoiceOver | 커스텀 요소에 접근성 레이블, 내용이 바뀌면 레이블도 갱신 |
| Samsung Tizen | Voice Guide | 포커스된 HTML 요소 안의 내용을 읽는다 — `role`·`aria-label`·`aria-labelledby`, 첫 요소 `autofocus`. `display:none` 은 읽지 않는다 |
| LG webOS | 오디오 안내 | `appinfo.json` 의 `supportsAudioGuidance`, ARIA 속성 |

- 토글은 **상태 + 동작**을 읽게 한다(예: "자막 켜짐"). 재생 컨트롤(재생·일시정지·되감기·빨리감기)에 이름을 붙인다.
- 자막·오디오 해설 설정이 있으면 시스템 설정을 따른다.
- 확인: 낭독기를 켜고 리모컨만으로 첫 실행·로그인·목록 끝까지·뒤로·재생을 한 번씩 돈다.
