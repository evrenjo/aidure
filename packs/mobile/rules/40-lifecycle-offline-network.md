## 메인 스레드

- 플랫폼 규칙은 둘이다 — **UI 스레드를 막지 않는다, UI 스레드 밖에서 UI 를 만지지 않는다.**
- 막히면 OS 가 끝낸다: Android 는 입력에 약 5초 응답이 없으면 ANR(서비스 시작·브로드캐스트 수신 처리에도 시간 제한), iOS 는 워치독이 실행·응답이 느린 앱을 종료한다. 흔한 원인은 **메인 스레드의 동기 네트워크·큰 데이터 파싱·큰 DB 마이그레이션·락 대기**다.
- 무거운 일은 데이터 계층(리포지토리 등)에서 백그라운드 디스패처·큐로. 결과만 UI 로 돌려보낸다.
- 개발 중 검사 도구를 켠다 — Android StrictMode, iOS Main Thread Checker·Thread Sanitizer. 새 경고를 남기지 않는다.

## 수명 주기·상태

- **OS 는 화면을 설정 변경(회전 등)에 다시 만들고, 메모리가 부족하면 프로세스째 없앤다.** 화면·진입점(액티비티·서비스·리시버·뷰 컨트롤러)을 데이터의 원천으로 쓰지 않는다.
- 상태를 나눠 둔다:
  | 무엇 | 어디 | 프로세스 종료 후 |
  |---|---|---|
  | 앱 데이터 | 로컬 DB·파일 | 남는다 |
  | 화면 상태 | 뷰모델·상태 보관자 | 사라진다 |
  | 복원에 필요한 작은 값(검색어·스크롤 위치·선택 ID) | 저장 상태(`SavedStateHandle`·`rememberSaveable`·상태 복원 API 류) | 남는다 |
- 저장 상태에 큰 객체(이미지·긴 목록)를 넣지 않는다. 저장 상태·뷰모델은 영구 저장소가 아니다.
- 데이터마다 **단일 원천**을 정하고 그 원천만 값을 바꾼다. 상태는 아래로, 이벤트는 위로 흐른다.
- 확인: 회전, 백그라운드 전환 후 복귀, **프로세스 강제 종료 후 복귀**(개발자 옵션·디버거)에서 입력이 남는지 본다.

## 백그라운드 작업

- 앱이 화면에서 사라진 뒤에도 끝나야 하는 일(업로드·동기화)은 **플랫폼 예약 작업 API** 로 — Android WorkManager(재시작·재부팅 후에도 유지, 네트워크 조건·지수 백오프), iOS 백그라운드 작업 API.
- iOS 는 백그라운드로 가면 곧 앱을 정지시킨다. 짧게 더 필요한 일은 백그라운드 실행 시간 연장을 **작업 시작 전에** 요청하고, 끝나면 **즉시** 종료를 알린다. 알리지 않으면 시스템이 앱을 끝낸다.
- 화면 수명에 묶인 코루틴·작업은 화면이 사라질 때 취소되게 한다. 사라진 화면을 만지지 않는다.

## 오프라인·동기화

- 프로젝트가 오프라인 우선이면 **로컬 저장소가 읽기의 단일 원천**이다 — 화면은 로컬을 관찰하고, 네트워크 결과는 로컬에 써서 반영한다. 최소한 네트워크 없이 읽기는 되어야 한다.
- 쓰기 전략을 데이터마다 정한다: 온라인에서만(실패하면 알린다) / 큐에 넣고 연결되면 전송 / 로컬에 먼저 쓰고 나중에 동기화. 충돌 해결 방식(예: 타임스탬프 기준 마지막 쓰기 우선)은 프로젝트·서버와 맞춘다.
- 네트워크 없음·느림·중간 끊김을 오류 화면이 아니라 상태로 다룬다. 재시도는 백오프로.

## 네트워크 보안

- **HTTPS 만** — Android 9 이상은 평문 통신이 기본 차단, iOS ATS 는 TLS 1.2 이상·전방 비밀성을 요구한다. 평문 허용(네트워크 보안 설정의 `cleartextTrafficPermitted`, 매니페스트 `usesCleartextTraffic`)·ATS 예외(`NSAllowsArbitraryLoads` 등)를 더하지 않는다. 꼭 필요하면 **도메인 단위**로, 이유를 적는다(ATS 예외 일부는 스토어 심사 때 사유를 요구한다).
- 서버를 고칠 수 있으면 예외 대신 서버를 고친다.
- **인증서 검증을 끄거나 모든 인증서를 믿는 신뢰 관리자를 만들지 않는다.** 개발용 CA 는 Android `debug-overrides` 처럼 디버그 빌드에만 적용되는 방식으로.
- 인증서 고정을 쓰면 **백업 핀과 만료일**을 둔다. 키 교체 때 앱이 끊기지 않는지 서버 쪽과 확인한다.

## 딥 링크·앱 링크

- 자기 웹사이트로 가는 링크는 **검증된 링크(Android App Links·iOS 유니버설 링크)** 를 쓴다. 커스텀 스킴은 다른 앱도 같은 이름을 등록할 수 있다.
- 들어온 URL 은 **URL 파서로 나누고 모든 인자를 검증한다.** 잘못된 형식은 버린다. 테스트에 형식이 깨진 URL 을 넣는다.
- 링크로 할 수 있는 동작을 제한한다 — 링크만으로 삭제·결제·민감 정보 표시를 하지 않는다. **링크에 토큰·개인정보를 싣지 않는다.** OAuth 로그인은 PKCE 를 쓴다.
- 링크 도메인 연결 파일(Android `assetlinks.json`, iOS 연결 도메인 파일)은 서버 쪽 작업이다. Android 파일에는 패키지 이름과 **서명 인증서 지문**이 들어간다 — 스토어가 서명하는 방식이면 로컬 키의 지문과 다르니 스토어 콘솔의 값을 쓴다.
