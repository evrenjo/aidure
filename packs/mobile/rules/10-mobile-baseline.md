## 모바일 앱 기본 원칙 (프레임워크 무관)

모바일 코드를 고치기 전에 확인한다. 절차·예시는 작업별 mobile 룰.

- **프로젝트의 기존 구조를 따른다** — 화면·상태 관리 방식, 저장소, 브리지 모양을 먼저 찾아 맞춘다. 새 패턴·라이브러리는 묻고 들인다.
- **메인(UI) 스레드에서 기다리지 않고, 다른 스레드에서 UI 를 만지지 않는다** — I/O·네트워크·큰 계산은 백그라운드로. 오래 막히면 OS 가 앱을 끝낸다(Android ANR, iOS 워치독).
- **화면 컴포넌트에 데이터를 맡기지 않는다** — OS 는 화면과 프로세스를 언제든 없앤다. 잃으면 안 되는 것은 저장한다.
- **권한은 필요한 것만, 그 기능을 쓸 때 묻는다** — 거부돼도 나머지 기능은 동작해야 한다. iOS 는 용도 문구 없이 보호 자원에 접근하면 앱이 종료된다.
- **비밀은 Keychain·Keystore 에** — 토큰을 평문 설정·웹 저장소에 두지 않는다. API 비밀 키를 앱에 넣지 않는다(번들은 누구나 열어 본다).
- **통신은 HTTPS** — 평문 허용·ATS 예외·인증서 검증 우회를 더하지 않는다.
- **딥 링크·인텐트·웹뷰 메시지는 외부 입력이다** — 모든 인자를 검증하고, 링크만으로 삭제·민감 정보 조회를 하지 않는다. 링크에 토큰을 싣지 않는다.
- **웹뷰에 네이티브 기능을 넓게 열지 않는다** — 브리지는 앱이 번들한 신뢰 콘텐츠에만.
- **로그·크래시 보고에 개인정보·토큰을 싣지 않는다.**
- **보조기기에서 동작해야 한다** — 조작 요소에 레이블, 충분한 터치 영역, 글자 크기 확대, 색만으로 구분하지 않기.
- **Android·iOS 중 하나만 확인했으면 "다른 플랫폼 미확인"이라고 적는다.**
