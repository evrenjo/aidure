## 서명

- **서명 자료는 저장소 밖에** — 키스토어·인증서·프로비저닝 프로필·암호는 CI 비밀·보안 저장소로. Android 서명 설정을 빌드 파일에 직접 쓰면 암호가 평문으로 남는다 — 저장소에 올리지 않는 별도 파일·환경 변수에서 읽는다. 로그에 찍히지 않게 한다.
- **앱은 수명 내내 같은 서명 키로** — Android 는 업데이트 때 인증서를 비교한다. 직접 관리하는 서명 키를 잃으면 **그 앱을 다시는 업데이트할 수 없다.** 스토어가 서명 키를 관리하고 개발자는 업로드 키로 서명하는 방식(Play 앱 서명)이면 업로드 키는 분실 시 재설정할 수 있다. 어느 방식인지 먼저 확인한다.
- 서명 단계를 끄거나 "실패 무시"로 바꾸지 않는다. 로컬 개발 빌드만 예외로 두는 기존 구분을 따른다.

## 빌드 변형

- **디버그 전용 설정이 배포 빌드에 새지 않게 한다** — 디버깅 가능 플래그, 웹 콘텐츠 디버깅, 개발 서버 주소, 평문 허용, 개발용 CA 신뢰, 상세 로그. 디버그 전용 설정은 빌드 변형·디버그 오버라이드처럼 **배포 빌드에 적용되지 않는 장치**로 둔다(Play 는 디버깅 가능 앱을 받지 않는다).
- 배포 빌드 로그는 줄인다 — 로그 수준을 빌드 설정으로 조절하는 기존 방식을 따른다.
- 비공개 API(Android 비 SDK 인터페이스 등)를 새로 쓰지 않는다 — 버전이 오르면 깨진다.

## 식별자·버전

- **앱 ID(패키지 이름·번들 ID)는 바꾸지 않는다** — 스토어·OS 가 다른 앱으로 본다. 키체인 항목·링크 연결·푸시 설정이 끊긴다.
- **버전 코드·빌드 번호는 단조 증가** — 스토어가 거절하고 업데이트 판정이 깨진다. 사람이 읽는 버전 문자열 규칙은 프로젝트 관례를 따른다.

## 대상 SDK·의존성

- **대상 SDK 를 올리면 동작 변경 목록을 확인한다** — 컴포넌트 `exported` 명시, `PendingIntent` 가변성 명시 같은 요구가 대상 버전에 묶여 있다. 스토어는 일정 대상 API 수준 이상을 요구하고 그 기준은 해마다 오른다 — 수치는 스토어 공식 문서에서 그때 확인한다.
- **의존성·SDK 는 배포 전에 최신 보안 패치 상태인지 본다.** 알려진 취약점이 있는 버전을 새로 들이지 않는다.
- SDK 를 더하면 그 SDK 의 권한·수집 데이터·개인정보 매니페스트를 확인하고 앱 신고에 반영한다(mobile 권한·개인정보·로컬 저장 룰).

## 스토어 심사에 걸리는 코드 변경

- **계정 생성 기능이 있으면 앱 안에서 계정 삭제를 시작할 수 있어야 한다**(App Store).
- **개인정보 처리방침 링크**는 스토어 메타데이터와 앱 안 양쪽에 둔다(App Store). Google Play 데이터 보안 양식도 처리방침이 있어야 작성된다.
- 앱 기능을 바꾸는 **코드를 내려받아 실행하지 않는다**(App Store). 원격 설정·웹 콘텐츠 갱신이 이 선을 넘는지 판단이 서지 않으면 묻는다.
- 숨은 기능·문서화되지 않은 기능을 넣지 않는다. 심사 메모에 새 기능을 적어야 하면 "심사 메모 갱신 필요"를 결과에 적는다.
- 스토어 정책은 바뀐다. 정책 판단이 필요한 변경은 공식 정책 문서를 다시 확인하고, 확인하지 못했으면 그렇게 적는다.

## 확인

- 배포 변형을 실제로 빌드해 서명·디버그 플래그를 도구로 확인한다(예: Android 서명 검증 도구, iOS 코드 서명 표시). "빌드가 성공했다"는 서명 확인이 아니다.
- Android·iOS 중 한쪽만 빌드했으면 다른 쪽은 미확인으로 보고한다.
