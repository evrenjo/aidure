## 클린 코드 공통

이 repo 의 기존 관례(포매터 · 린터 설정 · 주변 코드의 이름 · 구조)가 먼저다. 아래는 관례가 없을 때의 기본값이다.
**포매터 · 린터 설정이 repo 에 있으면 고친 뒤 그 도구를 돌린다.** 없으면 새로 설치하거나 설정 파일을 만들지 않고, 필요하면 사용자에게 제안만 한다.

### 이름
- 무엇을 담는지 드러내는 온전한 낱말로 쓴다. 약어는 그 프로젝트 · 분야에서 널리 쓰는 것만. 한 글자 이름은 몇 줄짜리 반복 변수 · 람다 인자에만.
- 단위 · 상태를 이름에 넣는다 (`timeoutMs`, `isExpired`). 불리언은 긍정형으로 (`isEnabled`, `!isNotDisabled` 금지).
- 한 개념에 한 낱말. 같은 동작을 `fetch` · `get` · `load` 로 섞지 않는다. 함수는 동사, 판정은 `is` · `has` · `can`.
- 이름이 잘 지어지지 않으면 설계를 의심한다 (하는 일이 둘 이상인지).

### 함수
- 한 추상 수준의 일. 줄 수가 아니라 "한 문장으로 설명되는가" 로 판단한다.
- 쪼갠 함수를 읽으려고 호출부와 오가야 한다면 쪼개지 않는다. 전달만 하는 얇은 함수를 만들지 않는다.
- 전제 조건은 앞에서 일찍 반환해 중첩을 줄인다 (중첩 3단 이내). 불리언 인자로 동작을 바꾸지 않고 함수를 나눈다. 인자가 많으면 묶는다.
- 조회와 변경을 한 함수에 섞지 않는다. 숨은 부작용을 두지 않는다.

### 클래스 · 모듈
- 인터페이스는 작게, 구현은 깊게. 호출하는 쪽이 몰라도 되는 것은 숨긴다.
- 같은 지식(형식 · 규칙 · 상수)은 한 곳에만 둔다. **새로 만들기 전에 비슷한 함수 · 모듈이 이미 있는지 찾아 재사용한다.**
- 지금 필요 없는 확장점 · 일반화를 만들지 않는다.

### 주석
- 코드로 알 수 없는 것만 쓴다: 왜 이렇게 했는지, 버린 대안, 제약, 단위 · 범위, 근거 ID · 링크.
- 공개 인터페이스에는 계약(입력 · 출력 · 오류 · 부작용)을 적는다.
- 코드를 바꾸면 근처 주석을 같은 변경에서 고치거나 지운다 (코드와 어긋난 주석은 버그를 부른다).
- 코드를 되풀이하는 주석, 작업 기록 주석("요청대로 수정"), 주석 처리한 코드를 남기지 않는다. 작업 기록은 커밋 메시지로.

### 자연어처럼 읽히는 코드
- 복잡한 조건은 이름 붙인 변수나 함수로 뺀다 (`if (canRetry)`). 매직 넘버는 이름 붙인 상수 · 열거형으로.

### 하지 않는 것
- 요청 범위 밖의 이름 바꾸기 · 구조 정리를 기능 변경과 한 커밋에 섞지 않는다.
- 쓰지 않는 코드 · import 를 남기지 않는다. 규칙을 맞추려고 함수를 기계적으로 쪼개거나 합치지 않는다.
