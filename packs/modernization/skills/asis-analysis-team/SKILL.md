# AS-IS 분석 팀

한 기능의 AS-IS 동작과 TO-BE 구현을 **사실 기반으로** 비교한다. 코드는 고치지 않는다 — 산출물은 보고서다.

## 역할

병렬 에이전트를 쓸 수 있으면 역할별로 나눠 띄운다. 없으면 한 에이전트가 아래 순서대로 수행한다.

| 역할 | 맡는 것 | 쓰는 도구 |
|---|---|---|
| **리더** | 범위 확정(기능·진입점·TO-BE 대상), 역할 배분, 결과 통합, 충돌 판정 | — |
| **레거시 분석** | 진입점 폐쇄 · 쓰는 표 집합 · 컬럼별 값 · 읽기 조건 | `asis-effects.js` · `asis-field-writes.js` · `asis-reads.js` · `check-cobol-coverage.py` |
| **데이터 분석** | 뷰 정의(필터인지 조인인지) · AS-IS↔TO-BE 이름 매핑 · 실데이터 분포 | `asis-tobe-map.js --where` · 읽기 전용 SQL |
| **TO-BE 분석** | 같은 계약의 TO-BE 쓰기·읽기 경로 전수 · 표마다 쓰는 곳 수 | 코드 검색 · TO-BE 쿼리 추출기 · `asis-tobe-diff.js` |

도구는 `packs/modernization/bin/`, 사용법 `packs/modernization/docs/asis-tools.md`. 레거시 소스 루트 `{{ws:vars.asis.sourceRoot}}`.

## 공통 지시 (모든 역할에 그대로 전달)

- 코드·DB 를 **바꾸지 않는다.** DB 는 읽기 전용 조회만.
- 레거시 검색은 `grep -a`, `sed`/`tr` 은 `LC_ALL=C`. 0건은 "못 찾았다" 로 보고한다.
- 판정마다 **확인됨(근거 파일:라인·쿼리 결과) / 추정 / 미확인** 을 붙인다. 추정을 사실처럼 쓰지 않는다.
- 도구가 `⚠ 폐쇄 밖 …` 을 내면 진입점을 넓히거나 그 사실을 보고에 적는다 — 무시하고 결론 내지 않는다.
- 뷰 이름·접미사만 보고 필터가 있다고 가정하지 않는다. 뷰 정의를 연다.
- **범위 밖 발견은 보고 끝 "범위 밖" 칸에 한 줄씩만** 적고 파고들지 않는다.

## 절차

1. 리더가 범위를 한 줄로 확정한다 — "<기능>: AS-IS <파일>(<진입점>) ↔ TO-BE <클래스들>". 모호하면 **선택지 질문**으로 확인한다.
2. 세 분석 역할을 띄운다. 레거시 분석이 표 집합을 먼저 내면 데이터·TO-BE 분석이 그 표 목록을 받아 이어간다.
3. 리더가 결과를 합쳐 `asis-compare` 스킬의 정합표 형식으로 만든다. 두 역할의 결론이 다르면 근거를 다시 대조해 판정하고, 못 가르면 **미확인**으로 남긴다.
4. 보고: 결론 한 줄 → 정합표 → 다른 항목 목록(수정 제안은 파일 단위) → 미확인 목록과 확인 방법 → 범위 밖 → 다음 단계 추천 한 줄(무엇을·왜·산출물). 다음 단계는 추천만 하고, 진행 방식은 사용자와 정한 뒤 시작한다.
5. 띄운 에이전트는 보고 전에 모두 종료한다.
