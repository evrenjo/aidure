## 데이터 마이그레이션 원칙

### 절대 규칙

- **소스는 읽기만 한다.** 소스 DB 에 INSERT/UPDATE/DELETE/DDL 금지 — 카탈로그 조회도 읽기만. 도구 코드도 소스 경로에는 읽기 전용·무잠금 세션(예: DB2 `WITH UR`)을 유지한다.
- **실 적재(run)는 사람이 직접 한다.** 에이전트 범위는 스텝 작성 · 소스 읽기 전용 검증 · 스텝 등록까지다. 등록 후 "적재를 돌려 확인해 달라" 로 인계한다.
- **타겟 스키마는 연결 설정으로 가른다.** 국가·법인 등 스키마가 다르면 연결(프로젝트)을 따로 만들고, 스텝 코드에 분기를 박지 않는다.
- **결정적 ID 의 네임스페이스는 절대 바꾸지 않는다.** 자연키로 UUID(v5 등)를 만든다면 네임스페이스가 바뀌는 순간 모든 참조가 어긋난다.

### 스텝 작성

- **자연키 = 소스 PK.** TO-BE 유니크 키가 아니라 AS-IS 소스의 PK(카탈로그에서 추출)로 결정적 ID 를 만든다. 문자 키는 RTRIM, 숫자는 정수 캐스트로 포맷을 통일한다.
- **PK 없는 소스 표**는 `ROW_NUMBER() OVER (PARTITION BY …)` 판별자를 자연키에 넣어 충돌을 사전 점검한다.
- **단순 pass-through 뷰(`SELECT * FROM base`)는 뷰가 아니라 베이스 표에서 직접** 읽는다. 뷰에 필터가 있으면 그 필터를 스텝에 명시한다 (`asis-tobe-map.js <VIEW> --where` 로 확인).
- **식별자 규칙** — 컬럼명 소문자 정규화, 밑줄로 시작하는 식별자 금지, 방언별 페이징. 스텝 SELECT 를 쓸 때마다 확인한다.
- **스텝의 `AS-IS AS tobe` 별칭이 매핑 근거다.** 한 AS-IS 표를 여러 스텝이 읽으면 1:1 적재 스텝이 정본이고 키 추출용 보조 스텝은 매핑 근거가 아니다 (`asis-tobe-map.js` 가 이 규칙으로 고른다).

### 스키마 스냅샷

- 적재 도구가 들고 있는 타겟 초기화 DDL 은 **손 스냅샷이라 밀린다.** 정본은 애플리케이션 실 DDL 이고, 재생성 시 실 DDL 통합본으로 통째 교체한다.
- 테이블 명세가 바뀌면 스냅샷·스텝·시드를 **같은 작업에서** 맞춘다. 스텝은 파일(YAML 등)과 도구 내부 저장소가 따로면 **둘 다** 갱신해야 실행에 반영된다.

### 검증

- 건수 대조(소스 vs 타겟), 자연키 중복 0, 필수 참조 고아 0 을 **쿼리로** 증명하고 결과 건수를 남긴다.
- 검증 기준값은 실제 적재에 쓴 소스(덤프·시점)로 잡는다. 정의에 적힌 소스와 실행한 소스가 다를 수 있다.
