원본 commands.md

아래 명령은 모두 aidure start 로 띄운 AI 채팅에서 말로도 된다 ("스프린트로 바꿔줘" · "FN-001 어디서 써?" · "리뷰는 GPT 로"). core 의 aidure 스킬이 말을 명령으로 바꿔 실행하고, 팀 범위 설정은 실행 전에 무엇이 바뀌는지 보여 주고 확인받는다. 채팅 안에서 하지 않는 것은 aidure start(에이전트 안에서 또 띄움) · aidure init · aidure remove(선택 화면 · 삭제) · aidure notify setup(터미널 화면) 뿐이고, 그때는 AI 가 명령을 알려 준다.

aidure --help 는 자주 쓰는 명령과 분류 8개(시작 · 설치 · AI · 모델 · 프로젝트 설정 · 팀 · 팀 규칙 점검 · 진행 · 기록 · 문서 · 알림 · 연동)만 보인다. 터미널에서는 분류를 골라 그 명령들을 보고, aidure help <번호> 는 그 분류만, aidure help --all 은 전체다. 명령마다 --help · -h 를 붙이면 그 명령의 사용법만 보이고 실행하지 않는다 (aidure upgrade --help). upgrade · reset · install 은 모르는 옵션이 있으면 실행하지 않는다.

aidure rules [list | off <ID> | on <ID>] [--repo <이름,…>]규칙이 팀에 맞지 않을 때킷이 넣은 규칙을 켜고 끈다 (필수 규칙 제외). --repo 는 스택 · 언어 규칙을 그 repo 에서만. 바꾸기는 packs/project/rules 에 replaces (repos: 를 더하면 그 repo 만)

aidure repo add [주소·폴더·이름]repo 를 더할 때clone · 링크(원격 없는 로컬 repo 도), 또는 이름만 주면 repos/<이름> 에 원격 없이 새로 만든다. 인자 없이 = 화면에서 방식(clone · 기존 로컬 폴더 · 새로 만들기)을 먼저 고른다 (레거시 제외. 기획 repo 면 뼈대는 aidure init-docs) → 스택 확인 → sync
aidure repo add … --group <그룹>repo 가 많아 폴더를 나눌 때repos/<그룹>/<이름> 에 받는다. 이미 그룹을 쓰는 워크스페이스면 화면에서 고른다 (그룹 폴더)
aidure repo move <이름> --group <그룹> · --no-group있는 repo 를 그룹 폴더로 옮길 때폴더 · workspace.json · 사람이 쓴 md 의 옛 경로를 고치고 sync (관리자)
aidure repo remove <이름> [--delete]repo 를 뺄 때workspace.json · 리뷰 대상에서 지우고 sync, 이름이 남은 문서(README 등)를 알린다. 폴더는 --delete 일 때만 지운다 (커밋 안 한 변경 · push 안 한 커밋이 있으면 거부)
aidure detectrepo 스택이 바뀌었을 때코드 repo 의 기술 스택을 다시 감지하고 고친다 → repo 별 규칙이 바뀐다
aidure detect --hint <스택> --contains <정규식>사내 라이브러리를 거쳐 쓰는 프레임워크가 감지되지 않을 때감지 힌트를 workspace.json 의 stackHints 에 더하고 다시 감지한다
aidure list워크스페이스를 찾을 때이 PC 의 워크스페이스 이름·킷 버전·경로. init 으로 만들거나 그 폴더에서 aidure 명령을 한 번 쓰면 오른다 (~/.aidure/workspaces.json, 지운 폴더는 자동으로 빠진다)
aidure help [번호|명령|--all]명령을 찾을 때인자 없이 = 자주 쓰는 명령과 분류 목록 (터미널이면 분류를 골라 보기). 번호 = 그 분류의 명령, 명령 이름 = 그 명령의 사용법, --all = 전체
aidure remove [이름] [--force]다시 만들 때

aidure init 화면#

◇ 프로젝트명           영문 소문자와 - 만, 문자로 시작 (예: new-stocker). 지금 폴더 아래 <이름>/ 을 만든다
◇ 시작 유형            ● 신규 구축 ○ 차세대 ○ 운영·고도화(SM 포함) ○ 분석·설계(ISP·ISMP)
   고르는 유형의 근거 · 넣는 repo · AI 가 하는 일이 목록 아래에 보인다
◇ 프로젝트 repository   하나 입력 → [추가] [확정] 반복 (분석·설계는 묻지 않음)
◇ 기획 repository       〃 (없으면 Enter)
◇ 이슈 repository       〃 (없으면 Enter)
◇ 레거시·현행 repository  차세대(필수) · 분석·설계(선택)만
◇ <호스트> 의 협업 도구  github.com·gitlab 이 든 주소는 자동 판단, 모르는 호스트만 묻는다
◇ 이대로 만들까요?
   … 워크스페이스 생성 · repo clone · 스택 감지 …
◇ repos/<이름> 스택     감지 결과 [맞음] [고치기] [건너뛰기]  (repo 마다)
   고치기 → 서버/클라이언트 → (클라이언트면) 웹·데스크톱·모바일·워치·TV → 프레임워크 → 세부(예: Spring MVC·WebFlux·Batch…) → DB
   모르는 단계는 Enter 로 건너뛴다
◇ 쓰는 AI              ○ Claude 만  ○ GPT 만  ● Claude + GPT  ○ AI 게이트웨이
   게이트웨이 → 찾은 주소 확인(또는 주소 · 키 환경변수 이름) → 모델 목록 조회 → 메인 모델 Claude · GPT
   역할 구성은 자동 (두 회사 = 섞기, 한 회사 = 한 회사 모델만). 단일 모델은 aidure ai compose single
◇ 팀 기본 모델 프로필   최고 · 표준 · 절약 · 역할별로 직접 고르기
◇ claude 에 항상 붙일 인자   없음 · 계획 먼저 · 파일 수정은 자동 · 확인 없이 실행 · 직접 입력 (이 PC 전용)
◇ 워크스페이스 repository 주소 → 지금 커밋·push 할까요?   (원격이 없으면 주소부터, 예를 누르면 push 까지)

Esc 는 이전 질문으로(첫 질문에서는 취소), Ctrl+C 는 전체 취소. 폴더는 마지막 "이대로 만들까요?" 에서 예를 누른 뒤에만 만든다. 프로젝트 폴더를 미리 만들 필요 없이 상위 폴더에서 aidure init 한다 (그 이름의 빈 폴더 안에서 해도 겹쳐 만들지 않는다). 안에 파일이 있는 폴더·이미 워크스페이스인 곳은 막는다. repo 이름은 주소 끝 폴더명에서 자동으로 정한다. 스택·역할·브랜치는 workspace.json 에서 고치고 aidure sync. 스크립트로 만들 때는 node <킷>/bin/kit.js init <폴더> --type new|modernization --packs … --docs … --legacy ….
