# 기획 문서 repo — 에이전트 작업 규칙

이 repo 는 요구사항의 정본이다. 여기서 문서를 쓰거나 고칠 때 아래를 지킨다.

- **ID 를 바꾸지 않는다.** `REQ-`·`SCR-`·`POL-`·`DEC-` 번호를 다시 매기거나 재사용하지 않는다. 폐기는 상태 `폐기` 로.
- **요구사항을 지어내지 않는다.** 기획자가 말하지 않은 동작·수치·예외는 쓰지 않고, 빈칸은 `확인 필요` 로 남긴다.
- 새 문서는 그 폴더의 `_template.md` 를 복사해 시작한다. 상태는 `초안` 으로 둔다 (`확정` 은 기획자가 정한다).
- 문서를 고치면 **맨 아래 변경 이력**에 한 줄 추가한다.
- `originals/` 의 원본이 바뀌면 `md/` 의 같은 경로 사본을 **같은 커밋에서** 갱신한다. 원본은 직접 편집하지 않는다.
- 용어는 `04-glossary/glossary.md` 를 따른다. 새 용어는 거기 먼저 추가한다.
- 결정은 `05-decisions/` 에 남기고, 영향받는 문서에서 그 ID 를 건다.
- 모순·누락을 발견하면 고쳐 쓰지 말고 **확인 요청 톤**으로 알린다 — "~를 보던 중 ~로 되어 있는 것으로 보입니다. 의도된 것인지 확인 부탁드립니다."
- 사람 이름 대신 역할(기획, 개발, 고객사 등)로 쓴다.
- md 나 화면설계서 장(`02-screens/*.html`) · 테이블 정의서(`06-data/*.md`)를 고치면 `aidure docs build` 로 `docs-site/`(ERD 포함)를 다시 만든다. Pages 를 켠 repo 면 같은 커밋에 넣는다. `docs-site/` 는 손으로 고치지 않는다.
- 구성도 · 흐름도는 ` ```mermaid ` 블록으로 쓴다. 상자 · 화살표 문자로 그린 ASCII 그림은 쓰지 않는다. 시스템 구성도(서비스 · DB 스키마 · 미들웨어 · 외부 · 서버 사양, 단계별)는 architecture 스킬의 견본을 따른다.
- 머리말 표는 짧게 둔다. 변경 내용은 맨 아래 변경 이력에 쓰고 머리말 칸에 쌓지 않는다.
- 테이블 · 컬럼은 기능 ID · 결정 ID 를 근거로 만든다. 근거 없는 테이블 · 컬럼을 지어내지 않는다.
- 커밋·푸시는 요청받을 때만 한다.
