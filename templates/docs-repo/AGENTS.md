# 기획 문서 repo: 에이전트 작업 규칙

이 repo 는 무엇을 만드는지의 정본이다. 메뉴 순서와 폴더는 `README.md` 의 「읽는 순서」, 정본 위치는 「정본은 사실마다 하나」 를 따른다.

- **사실은 정본 한 곳에만 쓴다.** 수치 · 코드값 · 화면 배치 · API 모양을 다른 문서에 다시 적지 않고 ID 로 가리킨다. 개수(테이블 수 · 화면 수)는 쓰지 않는다.
- **ID 를 바꾸지 않는다.** `REQ-` · `FN-` · `AC-` · `SCR-` · `API-` · `POL-` · `DEC-` · `Q-` 번호를 다시 매기거나 재사용하지 않는다. 폐기는 상태 `폐기` 로.
- **요구사항을 지어내지 않는다.** 사용자가 말하지 않은 동작 · 수치 · 예외는 쓰지 않고 미결 목록(`90-decisions/open-questions.md`)에 올린다.
- 새 문서는 그 폴더의 양식(`_template.md` · `_template.html`, 없으면 그 폴더 README 의 표)을 따라 시작한다. 상태는 `초안` (`확정` 은 사람이 정한다).
- 결정 · 개정 경위 · 변경 이력을 본문에 쌓지 않는다. 결정은 `90-decisions/` 에 남기고 영향받는 문서를 **같은 커밋에서** 고친다. 이력은 git 이 남긴다.
- **코드 · 화면이 문서와 다를 때**: 판정을 먼저 보인다 (정본이 맞음 → 코드를 고칠 일 · 구현이 맞음 → 문서를 고칠 일 · 판단 불가 → 미결). 문서 고치기는 개발 워크스페이스의 설정 `vars.docs.syncMode` 를 따른다: `approve` = 사용자 승인 뒤 정본 한 곳을 고치고 결정 ID 를 단다 (결정이 없으면 `제안` 으로 새로 만든다), `ask` = 고치지 않고 미결 목록에 한 줄. 이 repo 에서 바로 작업할 때는 워크스페이스 설정을 모르므로 고쳐 쓰지 말고 확인 요청 톤으로 알린다 ("~를 보던 중 ~로 되어 있는 것으로 보입니다. 의도된 것인지 확인 부탁드립니다"). 사용자가 고치라고 하면 정본 한 곳만 고친다.
- `originals/` 의 원본이 바뀌면 `md/` 의 같은 경로 사본을 같은 커밋에서 갱신한다. 원본은 직접 편집하지 않는다.
- **규모 판단은 `00-overview/scale.md` 의 수치로 한다.** "과하다 · 필요 없다 · 충분하다" 를 짐작으로 쓰지 않는다. 수치가 없으면 묻고 거기 남긴다. 규모에 기대는 결정은 결정 기록의 「전제한 규모」 에 그 수치를 적는다.
- 용어는 `00-overview/glossary.md` 를 따른다. 새 용어는 거기 먼저 추가한다.
- 사람 이름 대신 역할(기획 · 개발 · 고객사 등)로 쓴다.
- md 나 화면 · 테이블 정의서를 고치면 `kedovi docs build` 로 `docs-site/` 를 다시 만든다 (손으로 고치지 않는다). Pages 를 켠 repo 면 같은 커밋에 넣는다.
- 구성도 · 흐름도는 ` ```mermaid ` 블록으로 쓴다. 시스템 구성도(서비스 · DB 스키마 · 미들웨어 · 외부 · 서버 사양, 단계별)는 `10-system/architecture.md` 양식을 따른다.
- 테이블 · 컬럼은 기능 ID · 결정 ID 를 근거로 만든다. 근거 없는 테이블 · 컬럼을 지어내지 않는다.
- 커밋 · 푸시는 요청받을 때만 한다.
